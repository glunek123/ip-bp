# 后续设计清单

更新日期：2026-09-15。此文件是待设计事项的唯一清单；当前任务进度见 [开发状态](project-status.md)。业务词汇和方案以确认后的字段、规则文档为依据，现阶段不创建业务表、角色或流程。

## 接收文档后的处理顺序

1. 登记输入文档路径、版本或文件指纹、来源、确认人/确认依据与状态。未提供确认依据的内容标为待确认；区分 Demo 观察、用户确认和推断。
2. 逐项检查下面的输入条件，记录已满足及缺失输入。字段和规则文档到齐不代表登录、供应商或部署条件齐备；仅暂停依赖缺失输入的事项。
3. 为可推进事项建立需求编号到设计、页面/API、实现文件和测试用例的对应关系。字段文档不是直接生成数据库的指令，先确定实体归属和规则。
4. 状态使用：等待输入 → 可设计 → 设计已确认 → 实现中 → 已验证。收到文档不能直接关闭事项；设计、实现和验收证据全部具备才标已验证。不适用项需有明确确认依据。
5. 每次设计/实现交付同步本清单和 project-status.md，保留输入版本、设计决定和验证证据链接；用户改需求时重新检查受影响项。

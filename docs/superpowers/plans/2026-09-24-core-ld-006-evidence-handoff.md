# CORE-LD-006 运营确认取证并移交实施计划

> 执行[核心主线设计](../specs/2026-09-21-core-business-mainline-roadmap-design.md)、[字段与动作契约](../specs/2026-09-21-core-flow-field-material-contract.md)和[线索模块 Spec](../../spec/v0.1/modules/leads.md)；只记录本 Slice 小粒度落点，不另立通用公证平台或重复状态台账。

**目标：** 运营在客户有效确认侵权后，明确选商品、材料精确版本、公证处和线上购买取证方式，原子创建可反查来源线索的待取证公证事项；原线索保留只读。后续明确新建取证批次可再生成另一事项，普通重试不可重复生成。

**边界：** 本 Slice 只交付移交入口、公证处最小可用主数据、事项来源快照及只读查看。不开始 NT-001 物流，不实现公证处外部账号、出证、案件或撤销更正。误建／撤销仍受 BQ-03 约束，不提供未决操作。

**实施：**

- [ ] 高风险后端：前向迁移建公证处、事项及所选商品／材料版本关系；复用现有内部身份、`lead.evidence.decide`、事务、审计、回执。服务端重查客户准入、有效客户侵权决定、线索范围、商品／材料归属与内容版本、公证处可用性、状态、版本和幂等。保存服务端操作人、时间及不可变来源快照；提供最小公证处和事项读写接口。
- [ ] 正式页面：在运营线索详情就地选择商品、材料、公证处，清楚提示移交后果；加载、可安全重试及成功反馈。线索和事项互相可达、刷新后仍可查看；客户端企业读取不因线索阶段变化意外失效，也不得泄漏公证内部字段。
- [ ] 聚焦验证与独立审查：先测正常、多批次、错误状态／版本／权限／部门、错误商品／版本／公证处、同键重放与异参、竞争、审计／回执失败回滚、客户与运营读范围；高风险实现经独立 Sol 审查，集成候选再独立 Final Review。
- [ ] 稳定候选门禁：`pnpm check:fast`、Level 3 完整门禁、空库和上一支持 Schema 迁移、独立测试库 API 及真实数据库浏览器链。结果记录于 VALIDATION；全部通过前不标完成、不推进 Current／Next。

**验收主链：** 管理员维护可用公证处 → 客户真实账号确认侵权 → 运营真实账号选定部分商品及截图版本并移交 → 待取证公证事项有精确来源和快照 → 原线索只读、双方按原有企业／部门边界读取 → 刷新仍在；再次明确建批次有独立记录，同一请求重放只有原记录。

# CORE-NT-008 公证事项列表列设置实施计划

> 执行：使用 subagent-driven-development，按仓库协作路由串行写入；高风险后端／迁移任务由 Sol 实施及独立审查，普通前端与浏览器验收由 Luna 执行。完成状态仅由路线图维护。

**目标：** 内部账号在公证列表调整自己的列显示与顺序，服务端保存，刷新、重登和新浏览器会话可恢复。

**依据：** [公证Spec](../../spec/v0.1/modules/notary.md#core-nt-008-列设置)，用户已批准 NT-008→009→010 排期。本次不包含导出、批量归档或新增业务字段。

**方案：** 在现有 leads 模块增加本人公证列表偏好，复用 ActorContext、CSRF、实时授权与请求层。事项编号和阶段保持可见；来源线索、公证处、创建时间可隐藏并调整顺序。偏好不携带业务记录，不改变读取投影。普通前向迁移和既有授权复用按 Level 2 验证；schema Task 仍须独立 Sol 审查。

## 固定契约

- `GET /api/v1/notary-matters/list-preference`、`PUT` 同路径；主体仅由当前 Actor 决定，不接受 userId／departmentId。
- 请求和响应均为 `{ order: string[], hidden: string[] }`。五个列键依次为 `businessNo`、`stage`、`sourceLead`、`notaryOffice`、`createdAt`；前两项固定，后三项可以换序。order 必须包含五项且无重复，hidden 只能包含后三项且无重复。
- 服务端默认显示全部列；未知／重复历史列键忽略，缺少的已知列按默认顺序补入，固定列不能被旧记录隐藏。输入未知键、重复键、固定列隐藏或额外字段返回400。
- 仅当前有效内部账号且有 `lead.read` 时可读写本人偏好；外部账号拒绝，撤权下一请求生效。偏好按账号保存，不因切部门或无列表数据改写他人偏好。
- 全量覆盖的 PUT 使用最后成功保存值；没有业务阶段变化，不引入 Command 回执、业务审计或通用偏好平台。界面只在保存成功后应用，失败保留草稿并允许重试；恢复默认也由服务端保存。

# CORE-NT-005 出证转案实施计划

> 本计划执行时先按 TDD 写失败测试；高风险模型、权限和 Command 在集成前由独立 Sol 审查，全部任务集成后做一次 Final Review。任务完成态以路线图和验证记录为准，本文件不预写验收通过。

**目标：** 真实公证处完成一次出证、归档公证事项并原子生成待匹配案件。

**架构：** 复用现有 `NOTARY` 账号绑定、私有材料服务、事项回执与审计；新建最小出证事实及案件模型，跨模块写入同一 PostgreSQL 事务。前端沿现有公证处壳层增加待出证入口，并以最小内部案件只读页证明转案结果。

**技术栈：** NestJS、Prisma/PostgreSQL、Vue 3、Vitest/Jest、Playwright。

## 全局约束

- 仅 `WAITING_CERTIFICATE → ARCHIVED`；公证处真实绑定办理；一本证书必须有编号、日期和至少一份真实 PDF／JPEG／PNG 文件。
- 多本、更正、退货、案件匹配与正式法院案号不在本切片；费用原身份和来源不复制。
- 使用 `backend/.env.test` 独立测试库和前向迁移，不重置开发或生产数据。

## Task 1：模型、迁移与受控材料

1. 先补 schema／材料规则的失败测试，确认出证文件类型、限制、阶段授权和冻结下载隔离；运行聚焦测试观察预期失败。
2. 增量建不可变出证事实、四类来源费用、最小案件及编号模型，新增公证书／披露材料类别和迁移；复用材料服务的上传、内容版本、冻结引用与下载再授权。
3. 运行材料／迁移聚焦测试，并在独立测试库随机 schema 验证空库和上一支持 schema 升级、约束与失败回滚。独立 Sol 审查 schema、安全范围和材料授权。

## Task 2：出证 Command 与只读投影

1. 先补真实数据库失败测试：成功出证与案件、跨公证处／撤权、无效文件／费用、旧版本／并发、同键重放／异参冲突、审计／回执／建案失败回滚。
2. 新增公证处出证请求 DTO、Controller、Command 及最小列表／详情；出证前事务内重校验全部前置，单事务冻结、归档、通过 `cases` 模块公开服务建案、审计和回执。
3. 由 `cases` 模块提供内部案件只读 API，按当前部门案件读取权限授权，不复用线索 SELF／TEAM 范围；单元、数据库和 OpenAPI 契约测试通过。独立 Sol 审查 Command、事务、费用与隔离。

## Task 3：真实页面与请求层

1. 先补前端 API 解码器及组件失败测试；扩展公证处列表／详情的待出证、上传、提交、成功记录与稳定错误处理。
2. 增加内部案件最小列表／详情与路由，展示来源和费用、不显示假法院案号；测试角色导航、刷新读取和禁止跨端跳转。
3. 运行相关前端聚焦测试、typecheck 和格式检查；普通 UI Task 自审并交接结果。

## Task 4：集成与收口

1. 集成后跑真实账号数据库／Chromium 主链，迁移专项和 `pnpm check:fast`；独立 Final Review 后修复并回归。
2. 冻结稳定候选并运行所属正式 Level 3 门禁及数据库型浏览器验收；只把实际通过的候选、命令和结果写入 VALIDATION。
3. 全部通过后才更新路线图完成态、唯一 Current／Next、project-status，解释并记录上下文快照；检查收口 diff 后按文档专项门禁收尾。本轮不推送、不合并远端。

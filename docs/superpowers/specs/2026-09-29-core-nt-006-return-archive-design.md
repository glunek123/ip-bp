# CORE-NT-006｜不出证退货归档设计

日期：2026-09-29。依据：CORE 主线设计、字段材料契约、REQ-NT-004、SD-15／26／41，以及本轮用户确认。本文件只确定 `WAITING_RETURN → ARCHIVED` 的单事项办理；不发起付款、结算、出证或转案。

## 已确认的办理语义

当前有效且覆盖来源线索的内部运营账号，在已有不可变 `NO_ISSUE` 决定的 `WAITING_RETURN` 公证事项上一次提交退货选择、适用的退款／运费事实和必填归档原因。三种选择对应三个归档类型，页面不再让用户重复选择：

| 选择          | 页面说明                     | 本次必须记录的金额状态                    | 不应生成的费用事实 |
| ------------- | ---------------------------- | ----------------------------------------- | ------------------ |
| `RETURN`      | 收到货后办理退货／退款       | 退款与退货运费分别为 `KNOWN` 或 `PENDING` | 无                 |
| `KEEP`        | 收到货但不退货、也不申请退款 | 无；仍须填归档原因                        | 退款、退货运费     |
| `REFUND_ONLY` | 不寄回货物，只办理退款       | 退款为 `KNOWN` 或 `PENDING`               | 退货运费           |

`KNOWN` 必填非负的人民币金额，允许真实的 `0.00`；`PENDING` 不存假零值。有正金额时，退款由运营明确选择指定收款方、运费明确选择指定承担方，均不默认客户或我方；候选为客户企业、我方、商家／平台、其他，选“其他”须填名称。零金额或待定金额无需猜测收付方。退款用正数及相对所选收款方的“退款收入”方向表达，运费用正数及相对所选承担方的“退货运费支出”方向表达；这两项只是业务费用事实，不代表已发起、已收到或已支付。完整财务科目、对手方、支付发起、实际回执和后续更正仍受 B11／B18／E03 约束。

已知正退款必须引用该事项原取证样品支出；原样品金额尚待定时不能登记已知正退款。服务端在同一事务内核对同一原支出全部已知退款的累计额不超过原支出，不设超额审批。原样品支出和退款分别留存，不覆盖原金额或只存净额。归档原因去空白后必填；归档日期、操作者由服务端生成。退货物流或退款截图本切片不作为必传门槛；现有附件继续按原权限读取，不创建虚假的凭证。

## 架构与数据流

新增专用 `notary.return.archive` Action，沿用现有内部账号、部门成员、来源线索范围、`expectedVersion`、`Idempotency-Key`、行锁、Serializable 事务、审计与事项 Command 回执。客户、公证处账号不能办理。服务端先核对账号及覆盖权限，再处理同键重放；相同键且请求内容相同返回原结果，不同内容冲突。正常提交重新核对 `WAITING_RETURN`、`NO_ISSUE`、原支出、金额及版本；不同键并发只有一个归档成功。

费用事实与归档事实使用不同的、通过事项和原支出关联的持久化记录，在同一事务中写入，再将事项置为 `ARCHIVED`、版本加一，写成功审计和幂等回执。任一写入失败整体回滚。原开箱、审核、出证选择和费用来源不改写；退货归档不创建案件或公证书。数据库以外键、唯一性及金额／状态约束守住错误绕过 DTO 的输入。前向迁移同时验证空库和上一支持 schema 的旧数据升级；已有 `ARCHIVED` 记录不能被误读为退货归档。

内部详情在 `WAITING_RETURN` 且有权时显示单次办理表单、状态影响、加载与稳定错误；成功后显示归档类型、原因、时间、退款和运费的已知／待定状态及实际选择的收付方。客户端继续按来源企业绑定读取最小归档结论和原有允许附件，不返回内部退款、运费或收付方。读取校验须区分原有不侵权归档、出证归档和本次退货归档，不把某一类 `ARCHIVED` 当成另一类。

## 验收与排除

聚焦和真实 PostgreSQL 测试覆盖三种选择及条件字段、非负金额和 `KNOWN/PENDING`、原支出引用与累计上限、不同键并发、旧版本、错误阶段／决定、无权／跨部门／外部账号、撤权下一请求、同键重放与异参、费用／归档／审计／回执任一失败整体回滚、数据库约束和旧归档读取。真实 Chromium 以运营密码登录，从不出证决定进入待退货，完成归档、刷新及重新登录回看；客户账号只能读取本企业最小归档结论，其他企业不可读。

本切片不实现付款或退款执行、实际资金结果、待定金额后续更正、普通重开、批量退货、额外归档类型、退货凭证必传规则或完整费用中心。待定金额归档后明确显示“待定”，不冒充财务已结清；其后续更正需另行确认并交付。NT-006 只有页面、API、数据库、迁移、权限隔离及浏览器闭环通过后才标记完成并推进路线图。

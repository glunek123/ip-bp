# CORE-NT-003 开箱侵权审核设计

日期：2026-09-28。状态：业务角色与切片边界已确认；尚未实施或验收。依据为 [SD-41](../../spec/v0.1/DECISIONS.md)、[公证模块 Spec](../../spec/v0.1/modules/notary.md)及[核心字段与动作契约](2026-09-21-core-flow-field-material-contract.md)。

## 目标与边界

对单个已提交真实开箱材料、仍处于 `UNBOX_REVIEW` 的公证事项，由有权运营人员或该事项来源客户企业的有效客户账号审核。结论仅为 `INFRINGEMENT` 或 `NO_INFRINGEMENT`；不侵权必须填写原因。侵权进入 `ISSUANCE_DECISION`（页面称“开箱待确认”）；不侵权在同一事务写结论、原因和归档事实并进入 `ARCHIVED`。两种结果都保存服务端审核人、身份类别、时间、不可变决定、成功审计和幂等回执。客户端与运营端刷新后读取同一结论。

本切片不办理 NT-004 出证选择、NT-005 出证转案、NT-006 退货、识别匹配、批量审核、归档撤销或重开，也不创建完整客户门户。客户在 `UNBOX_REVIEW` 状态上作出不侵权决定，不等于获准操作已经归档的事项。

## 身份、读取与页面

- 运营使用现有公证事项详情，须为当前有效内部账号、持有新增的最小开箱审核 Action，且该 Action 的独立授权范围覆盖来源线索；不能以 `lead.read` 或 NT-002 上传权限代替审核权限。
- 客户使用既有真实账号、会话及企业绑定。服务端每次请求核对账号、绑定、部门、来源线索客户身份及当前状态；撤销或停用后下一请求不得读取或审核。客户只读取本企业公证事项的最小审核摘要、明确属于该事项的所选商品和已冻结开箱照片；不暴露内部物流、寄件人、费用、团队信息或其他事项材料。客户入口从已有客户端线索详情可发现多取证批次，并提供最小待审核列表／详情与照片下载。
- 照片下载仍复用私有材料存储，但服务端必须以 `NOTARY_OPENING_PHOTO` 的事项所有者、已提交动作冻结的精确材料／内容版本引用、同部门与绑定企业共同校验；不能因为知道材料 ID 就下载未提交、其他批次或其他企业的照片。内部原有读取范围不扩大。
- 两端都在提交前说明结果后果：侵权交运营决定是否出证，不侵权立即归档且普通入口不能撤回；请求期间显示加载，成功后重读事实，错误保留选择并给出稳定反馈。不预选侵权或不侵权。

## Command 与持久化

内部端和客户端各有薄入口与独立读取 DTO，共用一个开箱审核 Command 和事务，不复制两套状态机。输入包含明确结论、条件原因、`expectedVersion` 与 `idempotencyKey`。Command 在事务中锁定目标事项，重新核对操作者实时授权／企业绑定、来源范围、开箱事实及冻结照片、当前状态和版本；首次合法提交以一次比较更新推进事项。两个角色竞争同一事项时只有一方成功，另一方得到稳定版本／状态冲突。

前向迁移仅增加本动作所需的状态值、不可变审核决定、客户或内部审核人身份关联与限定本动作的统一回执；原 NT-001／002事实及引用保持不变。新回执分别以可验证的内部部门成员或客户企业绑定关联操作者，不借用强制内部 DepartmentMembership 的旧公证回执外键。相同操作者同键同请求重放返回原结果，同键异参冲突；撤权后的重放仍拒绝，决定／归档／审计／回执任一步失败整体回滚。归档后的撤销或重开仍由 BQ-03 单独批准，普通审核页不提供入口。

新增 `ISSUANCE_DECISION` 与 `ARCHIVED` 后，同步已合并的公证事项列表筛选、同范围计数、侧栏标签和前端严格解码器；来源线索仍留在线索历史，不重新进入线索工作队列。尚未交付的 NT-004／005／006 阶段不显示可点击的办理入口。

## 验收与后续依赖

本切片按 Level 3 核验：两种真实账号分别完成侵权与不侵权结果；其他企业、其他部门、未获内部审核 Action、待取证／待开箱事项、未冻结或其他事项照片、停用／撤销账号均被拒绝。覆盖版本过期、同键重放与异参冲突、运营和客户并发竞争、决定／审计／回执故障回滚、空库与上一支持 schema 的迁移、刷新和重登录后的数据库型浏览器读取。独立 Review 重点检查外部身份、材料字节隔离、事务与归档边界。

NT-002 已有运营开箱入口，但没有公证处账号和入口。按用户确认的顺序，NT-003 完成后先交付 `CORE-NT-007`：公证处账号与明确公证处／部门绑定、最小待开箱事项读取及复用 NT-002 开箱 Command 的真实办理入口；只可处理获分派给该公证处的事项，不因公证处名称或同部门关系扩大范围。该补齐通过真实账号、数据库和浏览器验收后，才能将“待取件开箱由公证处和运营均可办理”称为完成，再进入 NT-004。未来 NT-005 的“待出证由公证处办理”须复用此身份并在其切片单独实现和验收；本设计不提前开放该动作。

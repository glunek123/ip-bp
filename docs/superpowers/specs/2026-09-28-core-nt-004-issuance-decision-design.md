# CORE-NT-004｜运营出证选择设计

日期：2026-09-28。依据：已确认的核心主线设计、字段材料契约、SD-41 和公证 Living Spec。本文件只细化 `ISSUANCE_DECISION` 的一次运营决定，不扩大 NT-005／006。

## 动作与边界

有权运营人员在单个处于 `ISSUANCE_DECISION` 的公证事项上明确选择 `ISSUE` 或 `NO_ISSUE`。前置开箱审核事实必须是 `INFRINGEMENT`。提交必须携带 `expectedVersion` 和 `Idempotency-Key`；服务端重新核对当前账号、部门成员、`notary.issuance.decide` Grant、来源线索范围、状态和版本。公证处与客户账号不得调用运营 Command。

`ISSUE` 原子推进到 `WAITING_CERTIFICATE`，`NO_ISSUE` 原子推进到 `WAITING_RETURN`。服务端生成 `decidedAt`，保留不可变决定、操作者、原／目标版本、成功审计和幂等回执；同键同请求重放原结果，异参冲突，双请求竞争只有一个成功。审计或回执失败必须整体回滚。已有开箱审核及冻结照片不改写，后续各端读取原审核结论和出证选择的允许摘要。

正式页面只在具备操作能力时显示两个明确选项，并在提交前说明影响；加载、成功、冲突与失败状态真实呈现。公证事项列表、阶段筛选和计数同步增加两个待办阶段，不把未交付的出证、退货或转案按钮显示为可用。保存草稿不是推进动作，本切片不增加无业务字段的假草稿。

## 实现约束与验收

复用现有 `NotaryMatter`、内部账号、`authorizeLead`、单事项行锁、事务、请求层和共享页面；以前向迁移增加两个阶段、最小固定 Action 和不可变决定模型，复用已有事项 Command 回执／审计基础。迁移不修改已执行文件，不重置非独立测试库。

聚焦测试覆盖两个分支、无权／跨部门／外部身份、错误审核前置、旧状态／版本、同键重放与异参、并发单胜、审计或回执故障回滚、撤权下一请求失效、两阶段列表与详情一致。迁移验证空库和上一支持 schema；真实 PostgreSQL／Chromium 从运营登录、开箱待确认、选择、刷新和重新登录证明持久化。NT-005／006 保持未实现。

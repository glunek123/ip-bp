# CORE-NT-005 出证转案小粒度设计

已确认边界见 [公证 Spec](../../spec/v0.1/modules/notary.md)、[核心字段契约](2026-09-21-core-flow-field-material-contract.md)和 [SD-41／42](../../spec/v0.1/DECISIONS.md)。本切片只办理 `WAITING_CERTIFICATE → ARCHIVED`，由当前有效且绑定事项公证处的真实 `NOTARY` 账号提交；运营与客户不得代办。

## 一次出证与案件来源

- 公证处先将 PDF／JPEG／PNG 公证书上传到事项私有材料，正式提交时明确选择至少一个有效内容版本；一事项本切片只登记一本公证书（一个证书编号和日期），多文件可属于该本。冻结所选版本，未提交草稿不改变阶段。多本和出证后更正不在本切片提供入口。
- 请求带 `expectedVersion` 和 `Idempotency-Key`，证书编号、业务出证日期、所选版本，以及 `needDisclose`；需披露时本切片可用真实披露文件满足材料门槛，不引入尚未批准的结构化字段。费用按公证／样品／调查／披露四类表达 `KNOWN`（非负两位小数，可为零）或 `PENDING`（金额为空）；已有样品费用必须保留原事实，不能在出证时覆盖。
- 同一 Serializable 事务内重校验账号、绑定、公证处状态、事项归属、`ISSUE` 选择及当前阶段／版本／文件、冻结文件版本、记录不可变出证事实与来源费用、归档事项、创建唯一来源案件 `PENDING_MATCH`、成功审计和幂等回执。任何一步失败整体回滚；同键同参重放原结果，异参冲突，并发仅一方成功。
- 案件有独立稳定 UUID 和业务编号，保留部门、客户、权利主体、来源线索／公证事项、负责人及费用来源；法院案号为空。费用按源事项身份读取，不复制成案件新支出或支付指令。此处只提供最小只读案件列表／详情入口，案件匹配、当事人和律师办理留给 CA-001。

## 读取与验收

- 公证处列表新增待出证分段；只有绑定的公证处可查看、上传、提交其事项，停用账号／绑定／公证处后下一请求失效。已归档事项只提供本人公证处本切片出证结果与冻结文件的必要只读视图；不开放其他事项或运营内部字段。
- 内部案件读取按部门和当前授权范围过滤；源线索负责人及团队用于既有运营范围判定。客户跨企业不得从出证／案件接口或材料下载穿透读取。UI 显示提交影响、加载和稳定错误，成功后从公证处出证记录可进入相应只读案件（若外部身份不应访问内部案件，则仅显示编号而不建立外部跳转）。
- 验收覆盖真实公证处账号、证书上传／下载、出证→归档→案件待匹配→刷新与重新登录，以及异公证处、停用、错误阶段、旧版本、幂等、并发、审计／回执／案件创建失败回滚和迁移空库／上一支持 schema。

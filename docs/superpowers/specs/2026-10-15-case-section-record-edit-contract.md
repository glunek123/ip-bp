## Storage

Each of six targets has an immutable typed Case<Name>RecordCorrection model: ExecutionMailing / ExecutionFiling / ExecutionFinish / Hearing / Judgment / Closure. Accessors: caseExecutionMailingRecordCorrection etc. Common fields: id, caseId, departmentId, exact target ID, priorCorrectionId, fromRevision, toRevision, correctionReason, recordedAt, recordedByUserId, auditEventId. Hearing/Judgment additionally trialRoundId, tied to original exact target. Closure additionally sourceClosureVersionId, tied to original currentVersion at command time; never change closure.currentVersionId or archive.closureVersionId. Finish stores business reason in businessReason; correctionReason is separate. Model business fields are typed like original roots.

Revision 0 is original data with no correction. Head is max toRevision for exact target, order descending; do not update root, Case.version, stage, current IDs, old workflow versions or receipts. fromRevision unique and toRevision unique per exact target+case+department; priorCorrectionId null iff fromRevision=0; otherwise exactly previous head. No mutable head pointer required. caseAnchorSnapshot JSON is supplied/overwritten by DB BEFORE trigger using locked original entire cases row; callers omit it (Prisma default {}) and deferred guard checks row unchanged at commit.

Five correction models have documents relation to Case<Name>RecordCorrectionDocument with correctionId/caseId/departmentId/materialId/contentVersionId (no documents for hearing). Same content-version FK and exact material scoping as original. documents nested create must supply case/department scope. Prior immutable files remain frozen. No append to an old correction's document set in a later transaction; guard must reject it.

New CaseSectionRecordEditReceipt with enum CaseSectionRecordEditCommand isolates new commands from old receipt trigger. Commands in table order: EXECUTION_MAILING_CORRECTION / EXECUTION_FILING_CORRECTION / EXECUTION_FINISH_CORRECTION / HEARING_RECORD_CORRECTION / JUDGMENT_RECORD_CORRECTION / CLOSURE_RECORD_CORRECTION.

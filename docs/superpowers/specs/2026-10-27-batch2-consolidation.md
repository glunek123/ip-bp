# 第二批：真正合并起诉实现切片

依据《运营优化需求｜第二批完整整合稿》第九项及 2026-10-27 用户后续确认。此切片在 S 候选 `0657870ce6e02b760fb6f1c49d142be8bc6a5417` 上实施。既有 `CaseHandlingGroup` 是办理组，仍独立保留；本切片新增法律意义的案件主从关系。

## 办理边界

- 只在待匹配列表选择 2–20 件；全部属于当前部门、同一客户和关联权利主体、同一平台与可核对的店铺 ID，且由当前内部账号本人办理、当前有部门案件读取和独立 `case.consolidate` 权限。代码与迁移只增加可配置动作，不向真实角色自动授权。
- 逐案提交当前版本、同一被告类型、姓名、证件号或统一社会信用代码和显式核对标记。既有被告不一致时拒绝；缺少可靠平台或店铺 ID 时拒绝，不单靠店铺名称。
- 默认创建时间升序、同时间 ID 升序确定主案；预览固定展示主案编号、全部参与案件和版本、总数。可以显式改主案，但改后须再次预览。执行时有序锁全部案件，在同一串行化事务重验权限、阶段、版本、身份和既有合案状态；同键同请求返回原结果，异参冲突。
- 主案保留原编号。从案保留原 ID、编号、来源、材料、费用和财务关联，关系由不可变成员记录表达；不搬移原账、不造新费、不重算金额。已有支付、退款、结算不构成合案阻碍，原账仍由原入口独立办理。暂不支持已并入案件或已有主案继续扩并，明确拒绝链式与重复合案。
- 从案的案件阶段或版本更新被数据库守卫拒绝；匹配和提前归档服务另有业务错误，从案列表与详情不显示可办入口。详情、历史、原材料下载和原案财务入口继续可读可办；材料读取逐来源重验现有授权。
- 默认案件工作列表、分页总数、阶段工作量计数及同条件 CSV 均排除已并入从案；查询从案旧业务编号时返回其主案，主案来源链接可进入从案原详情。批量提前归档先检整批有无从案，有则整体拒绝且不写批次回执。历史案件数与财务报表定义不因合案重算。
- 主案来源读取按原案、原线索、原公证、商品 ID、截图或公证材料的精确版本 ID 汇集；每项保留原 owner。后续立案证据来源引用需沿原权限验证，不复制文件或赋予主案读取者新来源权限。
- 立案来源版本在 `case_filing_consolidation_sources` 保留原材料 ID、版本 ID 和来源案件 ID。主案立案历史读取该表后逐原 owner 重新鉴权；商品、版本和原费用展示分别按稳定 ID 去重，逐案来源仍保留。

## 验收边界

定向测试覆盖权限/阶段/版本、默认及显式主案、被告与店铺冲突、重试与竞态、原账未移动、从案阻断和原办理组不变。迁移只保存源稿并作静态审查；不执行数据库、应用、远程下载、真实授权、推送或部署。真实 PostgreSQL 触发器、查询计划及页面操作留待 root 获授权环境集成验收。

待 root 获授权的一次性环境运行 `tests/e2e/batch2-case-consolidation-migration.spec.ts` 与 `tests/e2e/batch2-case-consolidation.spec.ts`。入口要求 `dev-cor-ops-batch2-20261027` 新容器、`127.0.0.1:15440/dev_cor_test`、独立 ready 标记和容器身份；只追加带随机标记的合成部门、账号、案件和原费用。数据库片验证 188 前旧事实、空库迁移、直接 SQL 约束；HTTP/页面片验证 S 查询分页/总数/导出，以及 M 待匹配列表勾选、预览、合案、原费用 ID 不变、从案阻断、主案后续立案引用从案精确版本和并发。后续立案采用隔离环境中的合成外部案与合成材料版本，手工推进主案到可立案阶段；该入口验证引用和读取，不代表完整正常公证到立案流程，仍需 root 做真实上传与下载授权抽检。

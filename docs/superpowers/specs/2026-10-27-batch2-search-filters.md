## 案件列表

- “我的案件”和“全部部门案件”共用一个关键词 `q`，数据库按字面、不区分大小写的部分匹配，在业务编号、法院案号、客户名称、权利主体名称、店铺名称、被告名称、法院名称、当前主办律师姓名之间 OR。旧律师条件因此已并入；金额、日期不进入关键词。
- 保持原账号、部门、本人负责及阶段范围。先在数据库叠加授权和筛选，再分页、统计总数。阶段分布计数保留当前范围和关键词，排除当前阶段条件。CSV 当前筛选导出使用同一查询构造与授权范围。
- 固定排序 `createdAt desc, id asc`。旧 URL 的分散文本和排序参数在列表页面读取时忽略，下一次查询或清空将其移出 URL。服务端即使收到旧排序参数也固定使用默认排序；案件列偏好只保存列顺序和显隐，不保存排序。
- 案件类型仍作为独立枚举筛选；关键词变化回第一页。查询与清空使用已应用条件，导出不采用未提交的输入草稿。

## 线索库与公证阶段

- 两个列表分别支持客户 ID、权利主体 ID 的搜索选择及店铺名称字面部分匹配；三项可以组合，线索库还能与既有关键词组合。筛选在数据库分页之前生效，总数和阶段计数使用同一授权基础条件。切换筛选回第一页，清空不留旧隐藏条件。
- 选项接口先执行 `lead.read` 范围校验，只查询该账号当前可读线索中实际出现的客户或权利主体，并按当前线索库状态或公证阶段进一步收窄；名称在服务端搜索，每次最多返回 20 项。公证选项还核实内部活跃账号。
- 公证“当前筛选结果”导出的预览和实际导出都携带相同三个条件，并在导出事务中重验读取及导出权限；勾选导出仍按明确选择的 ID。列表、计数及导出不从当前页做本地过滤。

## 权利主体与历史文字

- 客户、权利资产、线索、公证及案件相关用户界面统一显示“权利主体”；实体 `RightsHolder`、主键和关联外键不变。联系人仍独立。
- 新建权利资产只选择关联权利主体；旧客户端如仍提交非空 `ownerText`，服务端明确拒绝，新建记录的该字段为 `null`。修订或撤下旧资产时沿用已有版本的 `ownerText`，详情仅在历史文字非空时展示为“历史登记文字”；不自动匹配、改写或删除历史记录。
- 线索、公证、案件及导出继续使用现有权利主体关联；本切片不改数据库 schema 或迁移。

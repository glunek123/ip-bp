# CORE-NT-007 公证处身份与开箱入口设计

日期：2026-09-28。依据：SD-41、公证模块 Living Spec、NT-002 开箱材料契约和已完成的 NT-003。本文只细化已确认的 NT-007 支撑切片，不改变 NT-004／005 的业务动作。

## 目标与边界

部门管理员在已有公证处主数据下创建、停用真实公证处账号；账号以用户名、密码和现有会话登录。该账号固定绑定一个部门内的一个公证处，不创建内部部门成员或角色分配，也不继承运营 SELF／TEAM／DEPARTMENT 范围。有效账号只看本公证处获分派事项的待开箱队列与开箱所需最小事实，上传真实照片并复用 NT-002 的单事项开箱 Command，将 `WAITING_UNBOX` 推进为 `UNBOX_REVIEW`。运营原入口保持可用。

不做 NT-004 出证选择、NT-005 公证处出证、审核、退货、批量开箱、账号自助、改绑公证处或跨部门授权。停用账号／绑定或公证处后，下一请求失效；历史开箱事实、审计和回执保留。管理员创建账号不是把公证处用户纳入内部权限体系。

## 选择与理由

沿用 `UserAccount`、`LocalCredential`、`AuthSession`、私有材料存储和 `NotaryOpeningService`，增加 `NOTARY` 账号类型及不可改绑的 `NotaryOfficeAccountBinding`。相比单独认证系统，这保留已验证的密码、限流、CSRF、撤销和会话能力；相比创建假内部 `DepartmentMembership`，不会误获运营操作或扩大企业／部门范围。公证处授权由账号类型、有效绑定、有效公证处及事项的 `notaryOfficeId` 精确相等共同决定，不用内部 `RoleGrant` 推导。

管理员端在现有公证处设置页提供账号创建、列表和停用／启用入口；服务端每次要求当前内部身份与 `notary.office.manage` 部门权限。公证端采用独立路由和最小 DTO，不复用运营详情的内部资料 DTO。登录会话返回 `principalType=NOTARY`、公证处标识和名称，内部部门列表与客户身份均为空；后端每次恢复会话重新读取绑定、账号和公证处状态。

## 数据、接口与安全边界

- 前向迁移增设账号类型和公证处绑定；绑定的用户、部门、公证处身份不可修改，仅可变更启用状态和版本。内部成员与公证处绑定互斥，账号类型由正式创建入口确定。
- 现有上传草稿、开箱事实、成功审计和开箱回执目前以内部成员外键约束操作者。迁移须保留既有内部记录并增设外部公证处绑定路径，确保每条新记录仍有真实 `UserAccount` 及恰好一种有效操作者关联；不得用影子内部成员或借管理员身份写历史。已提交开箱事实仍不可变。
- 管理员接口为 `GET/POST /api/v1/notary-offices/:id/accounts` 与 `PATCH /api/v1/notary-offices/:id/accounts/:userId/status`；密码仅在创建请求中出现，响应不回传密码或哈希。创建、停用及重新启用写成功审计；状态变更撤销既有会话。
- 公证端接口为 `GET /api/v1/notary-portal/matters`（待开箱分页列表）、`GET /api/v1/notary-portal/matters/:id`（本公证处最小详情）及 `POST /api/v1/notary-portal/matters/:id/opening`。详情只含事项编号、当前阶段／版本、取证日期、已登记物流、寄件人已知值和本事项开箱照片；不提供客户资料、费用、内部备注、团队、其他事项材料或运营权限。提交继续要求 `expectedVersion` 和 `Idempotency-Key`。
- 公证处照片仅可在绑定事项的待开箱阶段创建和上传；读取待提交材料限该账号自己上传的照片，提交后只开放本事项冻结的开箱照片。材料列表、字节下载、删除／恢复及直接调用内部接口均由后端校验，不能用猜测 ID 绕过。
- 同一个 NT-002 Command 在事务锁内重新检查身份与事项绑定、状态、版本、照片版本归属和数量；成功写一次开箱事实、服务端操作者／时间、冻结照片、审计及回执。相同键同请求重放原结果，异参同键、旧版本、错误状态及越权稳定拒绝；撤权后重放也拒绝。并发运营／公证处提交只有一方成功，任一审计或回执失败整体回滚。

## 验收

真实管理员建账号→公证处密码登录→只见分派给本公证处的待开箱事项→上传照片并提交→刷新读取已保存开箱事实及允许的照片；运营原开箱链不回归。数据库验证跨公证处、跨部门、无绑定／停用／撤权、内部接口越权、未提交及其他事项照片字节隔离、旧版本、重放／异参冲突、并发、失败回滚和空库／上一支持 schema 升级。独立高风险 Review 先于最终 Level 3 门禁；本切片通过后才可将 NT-007 标记完成并推进 NT-004。

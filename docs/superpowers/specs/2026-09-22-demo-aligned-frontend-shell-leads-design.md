## 目标

将正式系统的布局和视觉语言尽量一比一对齐业务提供的 v158 Demo，同时保留正式系统已有的 Vue 路由、真实 API、权限校验、表单校验、数据持久化和错误处理。

首批交付范围为登录后全局壳层、线索列表、线索新建／编辑和线索详情。Demo 只是视觉与交互参考；其静态数据、`localStorage`、内联 JavaScript、未批准字段和演示性业务流转不进入正式系统。

### 首批包含

- 仅显示已实现且当前账号有权访问的导航项。
- 线索二级导航及四种已批准状态的真实数量。
- 对齐 Demo 的设计变量、间距、字体、按钮、表单控件、表格、卡片、状态 Pill、空状态和响应式行为。
- Demo 风格的线索列表、新建／编辑和详情页。
- 客户和人员与权限页首批只完成壳层接入：移除重复的旧页头和外层布局，不改其内容结构与业务交互。

## 架构

### 共享壳层

登录后路由统一进入可复用壳层。`App.vue` 只根据会话选择公共路由或登录后壳层；`AppShell.vue` 负责退出、已有管理导航权限判定、侧栏、顶栏、面包屑、路由激活态和内容插槽。业务页移除重复的品牌头和外层 `workspace` 结构，只渲染自身内容。

桌面端为 Demo 同款 232px 固定侧栏、右侧主栏、吸顶 56px 顶栏和最大 1440px 内容区。侧栏包含品牌、已实现导航和登录人摘要。顶栏只显示面包屑和真实可用动作。

侧栏不显示死入口；后续核心模块在其正式路由和能力落地后再加入。

### 样式基础

正式设计变量扩充为 Demo v1.5 色板和 4px 间距体系。继续使用现有 Element Plus 按需引入，由正式 CSS 统一约束视觉：

- 紫罗兰 `#5E6AD2` 是唯一主强调色。
- 画布 `#FCFCFD`、表面 `#FFFFFF` 和 1px hairline 构成层级。
- 卡片和页面主体不使用阴影，阴影仅供浮层使用。
- 标准控件高 32px、圆角 6px。
- 正文 14px，分区标签 11px；编号、日期、数量和金额使用等宽字体与等宽数字。
- 单一视图最多一个主按钮，且仅用于推进流程。

不直接复制 Demo 的巨型 HTML、内联事件和单文件样式，而是转换为可维护的 Vue 组件和共享 CSS。

## 线索导航与数据流

进入线索路由时展开线索导航组，包含全部、待推送、线索待审核、线索待确认和线索已归档。四种状态数量继续来自现有 `listLeads` 响应，不使用 Demo 假数据。

首批由壳层在进入线索路由时请求轻量首页以获取计数，在可能改变计数的线索路由切换后刷新。列表页继续独立管理分页数据和筛选。本设计接受首批多一次只读请求，不为纯视觉迁移新增后端契约。

面包屑和导航激活态由 Vue 路由派生；客户和人员与权限导航继续遵循已有权限。

## 线索页面设计

### 线索列表

主区使用 Demo 的紧凑页头、工具栏和 hairline 表格。状态筛选移入侧栏二级导航。表格列固定为：操作／线索编号、状态、平台、店铺、商品数、发现时间和最近更新。商品数直接使用 `products.length`，不在列表中自造销量或销售额汇总语义。点击行或明确的“详情”操作进入正式详情路由。

分页、加载、请求失败和空数据保持显式状态。空状态说明为什么为空并提供下一个真实可行的操作。搜索、批量操作和导入在对应后端切片完成前不显示。

### 新建与编辑线索

新建与编辑保留可直接访问的独立 URL，保证刷新、直达链接、浏览器历史和未保存表单行为可预期。内容采用 Demo 的紧凑双列表单、分区标签、商品紧凑行、估算展示、统一上传区和底部操作区。

已有正式行为不变：只能使用已准入客户；权利主体随客户联动；来源限定可用平台；校验聚焦首个错误字段；截图走正式私有文件 API；新建保留幂等键和预留归属重试；编辑保留版本校验。

没有已准入客户时，保留已实现的引导空状态，不展示无法提交的表单。

### 线索详情

详情页使用 Demo 的紧凑页头、状态 Pill、三列事实网格、商品明细表、附件区和记录信息区。所有值来自正式线索、客户、权利主体和材料 API。次要关联查询失败时，继续降级显示稳定标识，不隐藏线索主体；下载失败在附件区就地显示。

首批不新增属于 `CORE-LD-002` 及后续切片的阶段流转和操作按钮。

## 响应式行为

- 宽度不小于 1280px：展示完整固定侧栏和 12 列内容布局。
- 768px 至 1279px：侧栏保留，详情宽网格降级，表格可横向滚动。
- 小于 768px：侧栏改为抽屉，表单和详情改为单列，操作区换行，表格横向滚动，触摸目标高度至少 40px。
- 宽度不小于 1680px：内容区以 1440px 为最大宽度居中。

## 错误与状态

视觉迁移不得将错误伪装为空数据或乐观成功。页面保留已有的加载、空数据、不可用、不存在、无权限、校验和操作错误状态。重试按钮调用原请求路径；写入期间按钮保持禁用或加载态；不新增死按钮或纯装饰动作。

## 验证

实施按回归测试先行的方式进行。稳定候选至少包含：

- 壳层导航可见性、激活路由、面包屑、退出和线索状态导航的组件测试。
- 更新后的线索列表、表单、新建／编辑和详情测试，证明现有业务行为没有被标记结构改动破坏。
- 前端类型检查、Lint、格式检查和完整前端单元测试。
- 使用真实测试数据库执行适用的核心线索浏览器测试。
- 在 1440px、1024px 和 390px 视口下检查壳层、列表、新建／编辑、详情和空／错误状态。
- 浏览器控制台不出现新的错误或警告。

## 交付顺序

1. 引入设计变量与登录后共享壳层，保证全部既有路由仍可用。
2. 迁移线索列表和状态导航。
3. 迁移线索新建／编辑和共享表单展示。
4. 迁移线索详情。
5. 运行聚焦回归、响应式视觉验收和最终变更集适用的正式门禁。

客户和人员与权限内容迁移作为后续纵向切片；共享壳层需允许它们接入，不再重写导航架构。

## 验收条件

- 桌面端壳层在侧栏、顶栏、内容密度、色板、间距和 hairline 层级上与 Demo 基本一致。
- 只有已实现且有权限的导航可交互。
- 线索状态导航使用真实数量，并生成已有 URL 筛选。
- 线索列表、新建／编辑和详情使用 Demo 对齐结构，不丢失任何已实现字段或行为。
- 正式前端不包含 Demo 静态数据、`localStorage` 状态或未批准流程逻辑。
- 已有 API、权限、数据库写入、文件处理和工作流语义不变。
- 最终候选的自动化测试和真实浏览器核心线索检查通过，且不出现新的控制台错误或警告。

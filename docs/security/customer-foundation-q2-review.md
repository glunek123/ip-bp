## 边界决定

| Boundary           | Required result                                                           | Review result and implementation evidence                                                                     |
| ------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Trusted actor      | `departmentId`、`userId`和`authorizationRevision`只来自身份Adapter        | 接受；Controller不从请求体读取这些字段。CUST-FND-002必须以`ActorContext`和测试身份Adapter的生产禁用测试证明。 |
| Grant evaluation   | 一个Grant同时覆盖客户动作与目标范围；不得把不同Grant拼成更大权限          | 接受；服务按单条Grant逐项求值，任一单条不完整即拒绝。必须覆盖“部门读取＋本人创建不能得到部门创建”负向测试。   |
| Query isolation    | 客户列表／详情在数据库查询中施加部门范围；不可访问ID返回不泄漏存在性的404 | 接受；查询谓词由授权服务生成并与客户ID同时进入查询。不得先全量读取后内存过滤。                                |
| Mutation isolation | `departmentId`由服务端派生；创建请求不能提交另一部门                      | 接受；DTO不暴露部门和负责人字段，未知字段由全局ValidationPipe拒绝。                                           |
| Revocation         | 每次请求重新读取或校验`authorizationRevision`；撤权在下一请求失败         | 接受；CUST-FND-002首批以持久化用户版本对比实现，不建立跨请求授权缓存。                                        |
| Audit              | 客户与审计事件原子提交；审计只含稳定ID，不含证件正文或完整个人信息        | 接受；CUST-FND-003使用一个Prisma事务，审计详情仅记录客户ID、部门ID、操作者ID和动作。                          |
| Test identity      | 只在测试环境启用，生产配置不可能激活                                      | 接受；Adapter构造时检查`NODE_ENV === 'test'`，模块只由明确测试装配使用；生产环境构造失败。                    |
| Migration          | 仅新增本地／测试迁移；不得执行共享或生产数据库                            | 接受；迁移文件可生成并在`postgres-test`验证，不运行生产或共享环境命令。                                       |

## 发现与约束

1. E01未提供实际身份提供方和会话参数，因此首批只验证应用内部稳定身份契约；不得宣称真实登录、撤销会话或MFA已经完成。
2. E02未提供对象存储条件，因此本批不实现证件上传、内容版本、下载或正式准入；不得用本地文件路径冒充生产存储。
3. 当前计划只实现`customer.read`和`customer.create-draft`。角色模板、Grant和分配使用可扩展数据结构，但不预建策略语言、案件权限或完整权限管理界面。
4. 前端菜单和按钮只改善体验；所有列表、详情和创建请求都由后端重新授权。
5. 当前审核允许开始内部实现，不代表最终安全验收、真实接入验收或上线准入。

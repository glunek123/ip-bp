# 开发规范

适用于正式系统；技术选择和待确认事项见 [技术基线](architecture.md)。工程骨架已落实相关检查配置；业务规范在对应功能实现时落实，不代表业务功能已存在。

AI 每次任务的状态维护、恢复顺序与文档同步遵循 [AI 开发规范](ai-coding.md)，当前进度集中记录在 [开发状态](project-status.md)。源码、说明和验证不一致时，交付仍视为未完成。

## 1. 代码、命名与模块

- TypeScript 开启 strict；外部不可信值以 unknown 接入并校验，避免 any 和无依据的类型断言。
- 普通文件和目录使用 kebab-case；Vue 组件文件使用 PascalCase；变量、函数使用 camelCase，类和接口使用 PascalCase。
- 业务模块使用稳定的英文名，后端模块文件遵循 NestJS 后缀。名称按确认的业务词汇确定，同一概念全项目一致。
- 单一文件围绕一种职责组织；重复逻辑确有复用需求时提取，避免为未来需求提前建立抽象框架。
- 对模块外暴露的服务明确输入、输出和错误。调用方使用公开服务，不直接访问另一业务模块的内部查询或数据库表。
- 生成文件通过生成工具更新；业务代码修改源定义。后端数据库类型不直接作为前端接口契约。

## 2. 前端行为

- 基础控件使用既定组件库；颜色、间距、字体和状态色从共享 CSS 变量引用，改动 Demo 时遵守其设计文档。
- 页面临时状态就近管理，Pinia 用于确有跨页面共享需求的状态。业务数据以服务端为准，不把 localStorage 当正式数据库。
- 页面通过统一接口层请求。显式处理加载、空数据、失败、取消和重复提交；错误不得伪装成成功或空列表。
- 表单执行即时校验以改善体验；权限和业务合法性由后端再次检查。
- AI 回填使用草稿；已有字段与候选值不同，提示用户选择。提交仅包含允许编辑的字段，不直接合并模型输出到业务对象。

## 3. HTTP 接口约定

- REST JSON 路径以 `/api/v1` 开头，资源路径使用英文复数和 kebab-case；字段使用 camelCase。
- 后端 DTO、运行时校验和 OpenAPI 描述保持一致。输入校验启用白名单并拒绝未知字段；转换采用明确类型规则，避免宽泛的隐式转换。
- 普通成功响应直接返回声明的对象；删除成功无响应体时使用 204。列表返回 `{ items, total, page, pageSize }`。
- 分页参数从 `page=1`、`pageSize=20` 开始，`pageSize` 上限为 100；超界或非整数返回 400。每个列表接口明确稳定排序及允许的排序字段。
- 统一错误结构为 `{ code, message, requestId, details? }`，配合真实 HTTP 错误状态。校验使用 400，未认证 401，权限不足 403，资源不存在 404，业务冲突 409，未预期错误 500。
- `code` 为稳定的大写下划线标识，前端不靠 message 文案判断业务；服务端保留详细异常，响应不返回堆栈、密钥或数据库原文。
- 响应中的可空字段用 null；更新请求中省略字段表示不修改，null 仅在该字段允许清空时表示清空。业务字段的必填、默认值及清空权限由审核需求决定。
- 请求编号由后端生成并贯穿日志和响应头 `X-Request-Id`；外部传入的关联信息与内部编号分开处理。
- 浏览器 fetch 封装统一基础地址、AbortController 和错误解析；请求超时可覆盖，普通 JSON 请求默认 30 秒。识别或批处理另定后台任务契约，不继承普通请求的同步执行假设。
- 具有副作用的请求不自动重试。新增或变更接口同步更新 OpenAPI，并检查现有调用方；破坏兼容性的变更先明确迁移方式。

## 4. 数据与迁移

- PostgreSQL 表、列采用 snake_case，通过 Prisma 映射到代码命名。新业务实体的技术主键默认 UUID 字符串；案号、外部编号等作为业务字段另行定义。
- 金额以 Decimal 存储，通过十进制字符串传输，计算使用 decimal.js；允许精度、币种和舍入时点按业务确认，不使用 JavaScript 浮点数直接累计金额。
- 业务日期使用数据库 date 和 `YYYY-MM-DD`；时间点使用 timestamptz，以 UTC 记录、ISO 8601 带时区格式传输，默认按 Asia/Shanghai 展示。禁止把业务日期自动当作午夜时间点转换。
- 有明确一致性要求的多步写入使用事务；唯一性和关联完整性同时由数据库约束维护。外部 HTTP 调用放在数据库事务之外。
- 表结构变更通过 Prisma Migrate 保存记录；共享环境已执行的迁移保持不变，后续修正增加迁移。测试环境使用同类 PostgreSQL，不临时改用 SQLite 掩盖差异。
- 删除策略、历史追踪范围及数据留存属于业务决定，不全局默认软删除或自动清理。
- 本地和自动化测试使用独立测试数据；数据库连接与密钥从环境配置读取，配置示例只包含占位值。

## 5. AI 与外部对接

- AI 首期目标为 API 识别并回填表单草稿；模型接入集中在 AI 模块，供应商 SDK 不进入页面或普通业务服务。
- 首个识别功能实现前定义允许输入、输出字段及运行时结构校验。材料中的文字是待处理内容，不得作为操作系统或修改权限的指令。
- 只将当前用户有权处理、且已确认允许发送的材料交给模型。权限、可写字段和业务校验由应用执行；模型输出不赋予额外权限。
- 模型失败、超时或校验不通过时返回可理解的失败状态，保留用户草稿，允许手动填写；真实调用预算和重试策略按具体能力确认。
- 业财协议以对方提供的文档和验证结果为准。实现时分开记录业务状态和推送状态，用稳定业务标识关联请求与结果。
- 推送失败重试应防止重复单据；超时可能代表对方已接收，应先按协议查询或核对，不盲目再次创建。实现前确认对方支持的幂等或对账机制。
- AI 和业财的自动化测试使用可控替身；只有明确授权的对接验证才调用真实外部服务。

## 6. 配置、日志与验证

- 环境配置集中声明并启动校验。生产必需项缺失时明确失败，避免悄悄使用开发地址、默认密钥或演示数据。
- 技术日志记录请求编号、事件、耗时和必要错误上下文；密钥、令牌、完整上传材料、完整模型请求响应不进入常规日志。
- 使用基线指定的测试工具。业务规则、错误分支、数据库约束和跨模块流程按改动风险验证；可逆的文档和样式微调不机械新增测试。
- 接口变更检查成功、非法输入和相关错误；涉及权限时检查越权；涉及金额时检查精度与舍入；涉及 AI 回填时检查无效输出和已有字段冲突；涉及推送时检查超时及重复请求。
- 工程已提供统一的开发、构建、类型检查、Lint、格式检查和测试 scripts；命令以实际 package.json 为准，运行准备见根 README.md。
- 骨架验收目标为前端请求后端健康检查、后端验证数据库连接，前后端构建及相关检查通过。检查结果按实际执行记录，不宣称未运行的测试通过。
- 文档交付核对链接、选型一致性、未决事项边界和规划/实现状态。说明新依赖原因、实际改动、验证结果和剩余限制。

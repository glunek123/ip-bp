# M02 正式系统输入候选：案件

状态：**待业务审核**。依据 [案件事实](M02-cases.md) 和 [字段字典](M02-cases-fields.md) 反向提出概念边界、规则问题及流程审核重点；不是 Prisma 模型、接口或已批准业务类型。

## 1. 候选数据模型与业务关系

| 编号／概念           | 由 Demo 支持的数据范围                                             | 关系与待决边界                                                                          |
| -------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| C-C01 案件主档       | 业务单号、客户、权利主体、类型、侵权类型、运营、来源店铺、当前阶段 | 身份主键与可变业务号分离是候选；稳定关联身份、客户／权利主体多重性尚未确认              |
| C-C02 案件当事人     | 被告类别、姓名／单位、证件、联系方式、住所；上诉人选择             | 名称不能直接充当当事人 ID；同名去重、多被告、角色变化和信息不全时可办理范围待决         |
| C-C03 律师承办与协议 | 律师／律所／联系地址、匹配日、结算模式、基础费、比例               | 是否一案多律师、历史转派、主数据更新与案件快照的关系 UNKNOWN；不从单个字段推断只能一人  |
| C-C04 诉讼办理记录   | 立案提交／正式受理、法院、诉调号／法院案号、开庭日期地点法官、判决 | 一审、二审、发回重审轮次是否独立记录，必须确认；当前顶层字段覆盖不构成正式历史方案      |
| C-C05 二审及裁判结果 | 上诉人、二审过程、裁判结果、判决日期／金额／费／退费               | 二审进展独立于案件主阶段；多轮审理与旧结果清理规则不能直接从四态推导                    |
| C-C06 执行办理       | 申请／确认／邮寄材料、执行提交／正式日期、执行案号／文书           | 执行更新何时转归档；是否允许重启或多次执行 UNKNOWN                                      |
| C-C07 案件材料关系   | 起诉、证据、送达、判决、执行、保全、调档、披露、结案材料           | 单／多文件、版本、所属轮次和原件存储需要 DD-06；Demo 文书名／正文混用须拆清语义         |
| C-C08 结案与资金记录 | 结案日期／金额／原因、归档类型／日期；付款／退费；双方结算输入     | 结案、归档、收款、结算是否独立状态；不能照搬已归档=已结算；费用／结算完整定义待 M04/M06 |
| C-C09 合并关系与来源 | 来源案件、来源商品／费用／文件快照、新案件、合并日期及冲突选择     | 是否保留源案可检索、何种数据跟随或冻结、外部引用迁移；公证归档是否确为业务动作待决      |
| C-C10 流程记录与日程 | 动作前后状态、业务日期、记录人／沟通内容、开庭事件                 | Demo log/timeline 两源不一致；正式审计／可编辑沟通记录／业务日程是否各有职责待决        |

模型关系草案：客户与权利主体 → 案件；案件 → 当事人／办理阶段记录／文书／资金记录／业务活动；案件 ↔ 来源线索、公证事项与合并来源。箭头只说明观察到关联，不代表已确认基数、外键或级联规则。所有键的原始代码证据在字段字典，不能直接按页面数量建表。

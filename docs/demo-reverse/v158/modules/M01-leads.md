# M01 线索：代码事实、规则和流程

版本：v158；提取日期：2026-09-16；第一次人工检查通过后串行提取。本文只陈述 Demo 事实，正式系统候选输入单独见 [M01 候选模型与决策](M01-leads-candidates.md)。固定五文件指纹及全文阅读记录见 [INVENTORY](../INVENTORY.md) 和 [COVERAGE](../COVERAGE.md)。下文 `A:Lx–Ly` 指 [demo/app.js](../../../../demo/app.js) 的真实物理行；`H` 指 [index.html](../../../../demo/index.html)。源码版本未改变。

## 1. 术语及实现边界

- 线索：`LEADS[]` 中的对象；不是正式数据库表。`id` 为 LD 编号；`caseNo` 是共享生成的“案件单号”，不是法院案号（A:L7837–7917）。
- 客户 `client` 与权利主体 `party` 是两个字符串；客户输入联想可以带出主体候选，但允许自由输入，未建立对象 ID 外键（A:L8621–8626、8784–8790）。不得把同名视为同一实体。
- `reason` 在此表示侵权类型，不是归档原因；归档使用 `archiveReason`。`caseType` 与侵权类型也不是同一分类（A:L8629–8659、8817–8837）。
- 页面“销售总额”是商品销量／评论数与单价的估算，不是实际交易流水（A:L7829–7834、8758–8764）。
- 四个阶段仅为浏览器数组状态；阶段配置中的运营／客户文案不构成身份认证或后端权限。共享存档与文件实现边界见 [ENTITIES](../ENTITIES.md)，本模块没有独立 HTTP 路由。

取证移交 A:L8556–8584：新公证对象有 `id, case, caseId, shop, stage, stageCls, push, expressNo, recv, recvAddr, operator, links, notarial, deadline, file, ent, photos, ocr, docNo, docDate, feeN, feeP, feeD, disclose, discloseInfo, office, refundAmt, refundFreight, archiveAt, archiveReason, fromLead, source, notes`。`caseId` 和 `fromLead` 都写线索 ID；`links` 是数字 0，不是线索商品数组。客户、主体、平台、原商品、截图、原案件单号及完整审核历史未作为独立字段转存。主体／平台／店铺被拼入 case 展示字符串，不能等同于结构化关系完整保留。公证 ID 按数组长度加一生成，不证明全局唯一。

跨模块：客户联想；共享案件单号生成器；公证新增；案件详情按线索关联展示（A:L12747–12848）；共享 save／导航。公证与案件可能按店铺回退查找线索，不是稳定外键；转出后影响需继续 M03 核对。无角色会话、后端授权或外部公证 API 事实可据此推导。

## 5. CSV、计算和边界

- 17 个表头见 A:L9060–9077；UTF-8/BOM 模板。解析支持单行引号和双引号转义，但先拆物理行，不能完整支持带换行的引号字段（L9137–9198）。
- 仅保留“客户或店铺名非空”的行；不校验标准表头、必填全集、重复、日期、枚举和 URL。多行逐个 unshift，显示顺序与 CSV 相反。取消／失败没有清理全局解析缓存，只有成功后清空（L9079–9198）。
- 金额＝Σ((qty>0?qty:cmt)×price)，不取整数、不舍入；输入实时重算 Number 与保存 numOf 不一致。数量为 0 时用评论数，负数保存可变正数。币种、精度、负值业务政策 UNKNOWN（L8758–8770、8812–8813）。
- 日期混用本地日期、UTC today 和 datetime-local；线索 ID 日期、案件单号日期、发现日期不必相同；生成序号基于当前数组，历史删除不占号（L7837–7917、8818–8819）。
- 列表单价用首个商品，数量／评论／销售额为汇总；搜索不包括 links.title；“本周” KPI 若挂载则使用固定起点 2026-08-31（L8116–8194）。
- 正常 UI 限制不等于提交函数限制；直接函数验证结果仅说明本地函数缺防护，不代表发现正式服务漏洞。

# M02 案件：代码事实、规则和流程

版本 v158，2026-09-16；M01 提取后串行开展。源码固定指纹见 [INVENTORY](../INVENTORY.md)，五文件全文阅读见 [COVERAGE](../COVERAGE.md)。`A:Lx–Ly` 指 [app.js](../../../../demo/app.js)。字段逐组见 [案件字段字典](M02-cases-fields.md)；候选正式输入与待决项物理分离在 [M02-cases-candidates](M02-cases-candidates.md)。

## 1. 术语及范围

案件是 `STATE.cases[]` 的本地对象，覆盖一审、二审、执行、结案及相关材料。`cust` 是客户，`client` 是权利主体；这与线索的 `client/party` 映射不同。`id/caseNo/no/mediateNo/execCaseNo` 存在冲突，不擅自统一。准备起诉文书／准备执行文书是导航分组，不是存储阶段。角色文案、模拟律师名单不是权限模型。现有部门隔离与四端方向只引用 INPUT-001。

本模块包含列表、详情、被告、律师匹配、阶段处理、一二审／执行、归档、合并、批量文书、时间轴、保全登记及导出。费用明细归 M04、结算公式及账单归 M06；本处记录关联与副作用，不提前宣称这些模块已完成。

## 4. 专项业务规则、例外与副作用

### 4.1 判决、二审与开庭

判决先读取并验证日期和判决书，再展示二次确认；确认才写 judgeReady，保留待判决（A:L2232–2272）。转执行直接函数仅校验案件存在（L2298–2305）。进入二审默认原告；被告需至少选一名称，写 role/names，未形成参与人稳定 ID（L2318–2367）。

二审普通提交先放 SECOND_UPDATE_PENDING；发回重审采用草稿并写 secondResult、返回转正式立案，不清除历史一审字段。改判／维持原判须填收到日期和判决书；改判才覆盖 secondJudgeAmt；原告上诉才采集 secondRefunds，否则置空。hasSecondInstance 依赖二审内容字段，不依赖 status 或上诉人字段，进入二审后可能尚不显示面板（L2373–2512）。

同步开庭会替换该案同类型自动事件并设置次日标记；清空日期直接返回，旧事件／标记仍存在。一审／二审卡片直接编辑没有调用同步函数。自动推进只对待开庭执行，比较字符串日期，非法日期／时区边界未全面执行验证（L2744–2777、4033–4047、6792、6832）。

### 4.3 合并起诉

入口 `mergeCases` 只取勾选且待匹配的案件，至少2件；客户（cust回退client）与权利主体字符串必须完全一致。其他被选阶段被忽略。13个 MERGE_FIELDS 中店铺并列、标的额求和；其他不一致值供选择／自定义，空自定义拦截（A:L6316–6448）。

`doMergeCases` 创建新待匹配案：生成新单号、店铺去重并列、numOf金额加和；结构化被告按姓名去重；来源深拷贝进 mergedFrom、单号进 mergedCaseNos；清空合并壳的模拟 expenses/links。每个源案新增公证“已归档”记录，原因合并起诉、mergedInto新案；源案从 STATE.cases 移出，随后统一save（L6450–6543）。

确定冲突：侵权类型出现在冲突表并能选择，但落地 reason 和标题仍取第一个源案；被告若有结构化数组也优先并集合成，非简单采用选择值；选择空值的 valOf 会回退源值。同名被告是否同一人没有证件比对。源案的其他外部引用是否应迁移，未见本函数统一处理。以上都是 Demo 行为，不能直接当正式合并规则。CT07 已动态证实 reason 差异。

### 4.4 归档、付款与删除

列表归档根据 **FILTER.status** 分支而不是逐案状态：筛选为待归档走终结归档，其余先填结案信息→待归档。已选集合可以含其他阶段。终结归档需原因，日期和类型有默认；普通归档可空结案信息且多案共用同一组付款数据（A:L3881–3957）。

付款任一字段非空算一行，不要求日期、双方、金额或凭证齐备；一次性付款初次打开保留历史多行，主动切换才裁行；阶段保存 number，批量保存 string。退费只留正金额，待归档可改退费状态。自动结算金额／手工覆盖调用 M06；详情仅因待归档／已归档就显示“已结案结算”，**未证明结算完成**（L2514–2692、13066–13113）。

删除实际只过滤案件数组；嵌套字段随对象消失，其他数组不级联。已归档创建、直接编辑状态及重新开启可以绕过归档原因或结案前置条件（L6242–6300、6633–6700、6875–6915、7509–7519）。正式删除／留存策略须业务另定。

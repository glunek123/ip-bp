# M05 证物／公证书：候选输入

依据 [M05事实](M05-evidence.md)，不是已批准设计。

| 编号  | 模型和规则候选                                                       | 待确认／纠偏                                                                                                 | DD／场景          |
| ----- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------- |
| E-C01 | 证物：稳定ID、物理编号、来源业务关联、名称／类型、保管位置、保管状态 | 案件ID、公证ID不可混为一个无类型关联；全站阶段／日期／律师使用同一关系；编号唯一范围待定                     | DD-01/04/06；ES01 |
| E-C02 | 公证书：一本一记录，编号、出证资料、电子文件与纸质证状态             | Demo可同案多本但仅处理首本；是否按本管理、是否一次出证多本待公证负责人确认，不将“案件级状态”直接定为正式模型 | DD-01/02/06；ES03 |
| E-C03 | 保管／移交／销毁业务记录候选                                         | Demo仅可变状态，未提供真实凭证；签收／销毁前置、地点与接收人、可逆范围UNKNOWN，需材料管理负责人决定          | DD-02/03/06；ES02 |
| E-C04 | 来源说明与备注分离                                                   | 历史source被统一备注覆盖，空值不可清除；应保留真实来源，明确每件／案件级备注和清空行为                       | DD-01/04/06；ES04 |

可以确定纠偏：正常空台账不重填演示种子；条件性未定义变量用明确关联店铺取值；创建／编辑使用稳定ID而非长度，不能改错同ID另一件；真实业务删除不应触发重新播种。销毁、删除和留存期限不是同一概念，尚未获授权规则不得擅自归并。

流程候选：公证出证生成待交付条目→登记实际编号／货架→按实际动作变更保管状态；公证书纸质件单独管理。自动“填货架=在库”仅Demo行为，是否足以证明入库待确认。正式设计、API、代码、迁移、业务验证尚未产生，ES01–06仅源码推导。

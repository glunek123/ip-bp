# M06 结算：模型及规则候选

依据 [M06事实](M06-settlement.md)。拆清四个概念：案件应结算金额、一次结算发起明细、汇总账单、实际收付款；Demo将它们的统计和状态混用，正式语义尚需确认。

| 编号  | 候选输入                                                                 | 冲突／待决                                                                                                      | DD／场景                   |
| ----- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- | -------------------------- |
| S-C01 | 结算条件与案件适用条件：客户比例、律师模式／基础费／比例、适用基数、版本 | 客户从稳定客户关联获取，不用权利主体名字及默认客户兜底；0≠缺失。BD-08已确认某案修改只影响该案，客户协议另行维护 | DD-01/05；ST01/02          |
| S-C02 | 一次结算发起：稳定ID、案件ID、侧别、次数、业务日期、金额、原因           | BD-09已确认标“已发起结算”，实际完成以财务结果为准；余额占用／释放、部分发起、重试、防重与更正待设计             | DD-02/05/08；ST04、SS05/08 |
| S-C03 | 账单及来源明细快照：各明细稳定ID、收付方、金额、条件及状态               | BD-07允许跨收付方，但必须逐项列明各方；撤销按稳定明细ID回退，不能数组位置；留存期限仍待确认                     | DD-01/02/06/08；ST03、SS07 |
| S-C04 | 财务收付事实与回执：金额、日期、外部身份和业务关联                       | Demo只有种子及空待回填字段；实际对接、凭证、回款拆分及拒付场景需协议和财务确认，不补造API                       | DD-05/08/10；M06流程8      |

规则提取不是认可当前Math.round至元的口径。币种、小数位、舍入位置、客户与律师条件独立还是存在总额上限、以结案额还是实收净额为基数均UNKNOWN。BD-05/06针对费用原支出退款及改删保护，不自动扩展为全部结算账单撤销规则。

将待归档条件的按钮限制落实为动作校验、所有资金写入的主体明确、重算不悄然变更已确认金额，是确定纠偏方向；具体业务门槛仍以 [DECISIONS](../DECISIONS.md)逐项决定。正式设计、接口、代码、迁移及验收尚未产生。

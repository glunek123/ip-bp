## 2. 实现边界

一个浏览器静态Demo、11个DOM视图、共享全局对象及localStorage。没有在五文件范围发现业务HTTP路由或fetch/XMLHttpRequest/WebSocket调用；外部字体及商品链接不算业务接口。保存异常可能吞掉，刷新和导入会补样例／归并历史值，空数组可能重新播种。它不证明多用户、数据库事务、真实附件、四端认证、部门隔离、财务或公证处对接已实现（M00/M09）。

本项目既有部门隔离／四端／分派方向只引用 [INPUT-001](../../deferred-design.md)，不纳入Demo代码事实。正式API、类型、数据库、迁移和实现尚未在本任务产生。

## 4. 当前流程和调用关系

### 4.1 线索、公证、案件主链

线索录入／CSV→待推送→线索待审核→侵权后线索待确认→取证新增公证并删除源线索。不侵权／不取证／批量归档是支路；归档后可编辑。公证在线取证→待取件开箱→开箱待审核→开箱待确认→待出证；出证确认→公证归档并生成诉讼案、证物、公证书，补公证费和样品费。线下调查后直接待审核，确认可直接提诉归档；不出证走退货／归档。详情通用推进绕过这条链且不保存，不是另一套获准规则（M01§4、M03流程表）。

案件16阶段当前主链：案件待匹配→待写诉状→诉状待确认→诉状待盖章→待提交立案→转正式立案→待开庭→待判决；判决登记仍待判决，另作二审抉择。二审发回重审→转正式立案；改判／维持或不进二审→待写执行材料→执行材料待确认→执行材料待盖章→待申请执行立案→强制执行中；UI执行更新仅保存，待归档也是先保存结案信息，列表另执行已归档。通用推进可与UI不同，新建和卡片可跳后期阶段（M02§3/4）。

## 5. 冲突和重复实现（保留两侧）

1. 单条／批量／编辑的必填与状态门槛不同：M01§4/5、M02§2/4、M03流程表；不可选择最宽松路径作为正式规则。
2. 客户统计读SETTLEMENTS／静态客户字段，结算中心读CUST_BILLS，客户历史另按月份去重；同名指标不能默认同源（M10跨模块／M06统计）。
3. expenses与fees双写、合并源快照分叉；openAudit与audit、logistics与expressNo、log与timeline、顶层与ov均存在写读分离（M02/M03/M04）。
4. 结算找客户误用主体且回退首客户；公式编辑改全局；显式0会回退标的额；程序结果不证明财务正确（M06）。
5. 样品费用显示净额而发起原金额；已发起／已支付直接改删、归档与结算完成混淆（M04/M06/M02）。
6. 真实新建、载入、渲染、识别可混入种子；不可读模板用内置、材料只存文件名，不能将“有显示”当真实证据（M00/M05/M09/M10）。

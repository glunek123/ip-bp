# 实体、字段族与配置盘点

范围与指纹见 [INVENTORY.md](INVENTORY.md)。下文位置均指 [app.js](../../../demo/app.js) 的物理行。这里只登记代码对象，不定义正式数据库实体。字段的长度、唯一性、精度、时区、必填、引用完整性和正式类型，除明确给出代码依据外均为 **UNKNOWN**。

## 使用方式与类型边界

实体字段族是人工归纳；逐个对象键及出现行见 [FIELD-INDEX.md](FIELD-INDEX.md)，逐个配置式字段的标签、控件、required/options/default 见 [FORM-INDEX.md](FORM-INDEX.md)。两者共同构成字段清单，不以本页摘要替代逐字段索引。

代码中的字符串、数字、布尔、数组是某次赋值的 JavaScript 形态，并非稳定 schema。例如 amount 同时经过样例值、表单和 numOf 转换；日期是自由字符串与 date 控件值并存；空值有空串、—、未填和缺属性。`statusClass`、`typeTag`、`opColor` 等是展示字段，不自动当作业务字段。

## 关系索引与 UNKNOWN

1. 客户 → 主体／联系人／资产是对象内数组（L1060–1090）；案件 → 客户通常以名称查找（L5489–5495），正式外键 UNKNOWN。
2. 线索确认取证 → 公证新增并删除源线索（L8478–8585）；公证保留 fromLead，但源记录可能已不在 LEADS。详情另按店铺／客户字符串回查（L10710–10725）。
3. 公证 → 案件写 notaryId（L10661–10679）；证物／公证书新增时 caseId 使用公证 id（L10372–10403）。关联解释见 evCaseOfKey（L12002–12007），不得将所有 caseId 统一为案件主键。
4. 案件 → 费用／结算／日历通过不同字段与名称关联；其中结算 caseId 使用 caseNoOf（L5839–5853）。删除客户或案件不等于这些数组已级联清理（L6875–6887、L7092–7103）。
5. 合并案件保留 mergedFrom 快照并移除原案件（L6450–6538）；实体存活、证物关联和费用双写的最终效果需模块核验。以上关系的正式基数、唯一性和事务要求均未批准。

# 领域模型与字段语义

本页为本版唯一字段字典；是概念模型，不是数据库schema。除明确BD／SD／INPUT和纠偏约束，实体拆分、约束及基数均待审核。各组末尾链接到固定模块字段事实；旧键只用于追踪，不能直接生成正式类型。

## 通则与关系

关系基数、来源留存和移交载荷的集中证据见[主链关系矩阵](preparation/RELATIONSHIPS.md)。费用与结算并非已确认的前后生成关系；结算计算依据与剩余决定见该准备包及REQ-ST-001，详细字段仍只维护在本页。

- 稳定记录身份、可展示业务单号、法院案号分别表达；各业务记录创建时生成自身业务单号，具体主键技术、编码格式和唯一约束由T01设计（SD-08）。名称可变，不作为唯一关联依据（FIX-03/11）。
- SD-01/11/22/30/33确认客户与权利主体多对多、主体可与客户相同，每条线索／案件选一个客户和一个主体；信用／证件号码精确重复在本部门内禁止新建，仅名称重复提示并记录继续原因。无正式证件只可保存客户草稿，不得进入正式取证或案件；结案后历史关系永久只读。两个部门各自维护客户档案，不跨部门提示或共享，也不增设权利主体自动查重。
- 线索→商品／材料／审核记录；线索→公证事项→案件；案件→当事人／审理／执行／材料／资金。SD-02确认一条只读线索可关联多个明确取证批次的公证事项；SD-27确认案件合并只形成可解除办理组，源案及其材料、费用和外部引用不迁移、不复制、不删除。批次撤销与更正见BQ-03，律师和审理关系见BQ-07，归档见BQ-08。
- 公证事项可能源于线索或合并原案归档，必须区分来源类别。合并归档不等同新取证；不同对象身份不得塞进无类型“caseId”。
- 费用身份不因中心／案件／合并来源视图改变；BD-12要求转案保留原费用来源与关联。汇总账单由明细构成，各明细保留收付方（BD-07）。
- “未填”“金额待定”“明确无／不适用”“明确为0”不混用；“—”“刚刚”、样式类、头像颜色、筛选和弹窗草稿不是业务事实字段。SD-26规定所有业务金额使用已知／待定状态：已知时金额必填、可为0且非负，待定时不得落假0；方向由业务类型表达，不使用负数。持久化类型、长度、精度、默认值和唯一性未确定时不擅自指定。
- 日期分业务日期、约定时刻和实际操作时间；SD-06确认业务时区Asia/Shanghai、开庭次日00:00推进，B16仍管延期更正。SD-05/26确认第一版人民币，每笔已知金额最终落定四舍五入到分、保留两位，中间计算和比例保留精度。SD-28将SD-04/24的角色与案件动作矩阵改为可编辑默认模板，授权必须同时覆盖操作和数据范围；操作者身份按SD-31接入，不能保存演示人名充当审计身份。
- 下表“门槛”是目标建议或已决定约束，非复述Demo所有required。未定门槛明确挂缺口；物理字段出现点仍由固定FIELD/FORM索引提供，不把技术临时键全部转为领域字段。

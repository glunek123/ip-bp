# KL 日历与日期事件

日历表达业务来源事件，不提供未经确认的法定期限、自动撤诉、自动续约或通知承诺。主链自动推进由REQ-CA-008负责。

依据：[固定事实](../../../demo-reverse/v158/modules/M07-calendar.md)、[候选](../../../demo-reverse/v158/modules/M07-calendar-candidates.md)、[决定](../../../demo-reverse/v158/DECISIONS.md)和[纠偏](../../../demo-reverse/v158/CORRECTIONS.md)。字段见[领域模型](../DOMAIN.md)，B/T/E见[缺口](../GAPS.md)，通用技术设计见[TD-BASE-04](../TECHNICAL-DESIGN.md)。本模块TD-SLICE、API、实现、迁移及正式测试未产生；所有AC为未执行目标场景。

## REQ-KL-001 事件来源、变更与取消

- 状态：纠偏约束＋待审核。来源：K-C01 K-C02 FIX-05 FIX-25。字段组：KL01/CA05/CA08。
- 目标／动作与结果：自动事件明确关联来源与案件，日期修改／清空同步更新／移除该来源事件及派生触发，其他事件保留。事件跳转使用明确关联，不用案号或标题猜首案；缺展示信息保留未知。
- 异常、边界及待决：历史快照或当前档案展示、手工事件维护、过期事件和推进后更正见BQ-08/BQ-11；提醒调度由T04设计。
- 依赖：BQ-08/BQ-11/T01/T04；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-KL-001：**给定／操作**：同案已有自动开庭事件D及非该来源事件，将开庭日D改E后再清空。**预期**：D自动事件消失，E再被移除；旧推进触发也失效，非该来源事件不变；不会按同名案件跳错。

## REQ-KL-002 提醒和统计范围

- 状态：待审核／范围待定。来源：K-C03 K-C04。字段组：KL01/RP01。
- 目标／动作与结果：SD-13确认客户可看本企业案件日历、律师可看本人负责案件日历；运营范围继续按主管／小组长／运营数据范围。日历、未来30日、全量分类指标分别明确统计范围；提醒发送与状态推进分开，不能从种子文案推导真实通知或法律期限。
- 异常、边界及待决：是否新增通知、渠道、接收人以及期限业务依据见BQ-08/BQ-11；统计范围见BQ-11。
- 依赖：BQ-03/BQ-08/BQ-11/T03/T04；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-KL-002：**给定／操作**：切换显示月份且事件集合不变，查看带明确范围标签的指标；查看种子式逾期文字。**预期**：各指标按已确认口径计算，不以显示月份暗示未实现过滤；不声称已发送提醒或执行撤诉。

# LD 线索

待推送→线索待审核→线索待确认→移交公证并只读留存；不侵权／不取证走归档支路。阶段名沿用Demo草案，已移交的正式呈现方式不预设为新枚举。

依据：[固定事实](../../../demo-reverse/v158/modules/M01-leads.md)、[候选](../../../demo-reverse/v158/modules/M01-leads-candidates.md)、[决定](../../../demo-reverse/v158/DECISIONS.md)和[纠偏](../../../demo-reverse/v158/CORRECTIONS.md)。字段只在[领域模型](../DOMAIN.md)维护；B/T/E编号见[缺口](../GAPS.md)，通用技术设计见[TD-BASE-05／TD-TRACE-UX-01](../TECHNICAL-DESIGN.md)。CORE-LD-001已产生最小待推送线索接口、PostgreSQL模型／迁移、运营端列表／新建／详情／编辑页面及真实数据库／浏览器测试；它只完成REQ-LD-001的手工录入与允许范围内编辑、待推送状态及四阶段计数投影。CSV、推送、客户审核、取证和公证移交仍未实现；下列AC只按实际证据判断，不因局部切片整体标记通过。

SD-08已将Demo清晰字段、状态及正常入口作为本版业务基线；以下不再把字段列表、Demo明确的计算或批量技术一致性提交业务人员逐项选择。例外权限和更正仍按BQ审核。

## REQ-LD-001 录入、编辑与商品估算

- 状态：Demo基线（SD-08）＋纠偏约束；CORE-LD-001手工录入／编辑子集已实现并通过真实PostgreSQL／浏览器验证，CSV仍待后续切片。来源：L-C01 L-C02 L-D01 L-D02 L-D06 L-D08 FIX-02 FIX-11。字段组：LD01/LD02/LD03。
- 目标／动作与结果：字段基线包括客户、主体、负责运营、来源、发现时间、平台／线下对象、店铺及ID、案件／侵权类型、披露标记、备注、材料和商品明细；商品记录URL、名称、销量、单价、评论数和估算额。创建、编辑、CSV使用同一语义；草稿可暂缺商品。估算沿用Demo明确规则：销量大于0时用销量，否则用评论数，再乘单价；原始销量、评论数和单价分别保留，估算不冒充交易流水。
- 异常、边界及待决：负数和非法数值不得取绝对值或静默归0，须明确报错；转出只读按REQ-LD-004；修改、审核和归档权限按BQ-03，金额通则按BQ-09。
- 依赖：B01/B08/B16/B17/T01/T04；正式操作者与数据范围统一受REQ-XM-001约束。相关批量、失败和重复控制见REQ-SH-004。
- AC-LD-001：**给定／操作**：商品销量2、单价1.5、评论3；另有销量0、单价1.5、评论3；再输入销量-2。**预期**：前两项估算分别为3和4.5，原字段各自保留；负数不能保存为+2或静默归0，错误保留用户输入。**实际证据**：CORE-LD-001 E2E对前两项分别验证HTTP边界`3.00`／`4.50`和数据库Decimal到分结果，负数及小数Count均返回`VALIDATION_ERROR`。

## REQ-LD-002 CSV预览、提交与取消

- 状态：Demo基线（SD-08）＋纠偏约束。来源：L-C01 L-C02 L-D02 L-D07 FIX-01。字段组：LD01/LD02/LD03。
- 目标／动作与结果：系统展示当前解析批次、逐行校验结果和疑似重复项，提交只针对本次已展示且明确选择的有效行。打开、取消、读取失败后旧批次不得被新会话提交；多商品使用与手工录入相同字段语义。
- 异常、边界及待决：不采用Demo允许缺客户且自动“—”的宽松路径；无效行不写入，用户可只选择有效行；并发解析回调、重复提交、文件大小和格式由T02/T05设计。
- 依赖：T02/T05；正式操作者与数据范围统一受REQ-XM-001约束。相关批量、失败和重复控制见REQ-SH-004。
- AC-LD-002：**给定／操作**：选CSV A→取消→重新打开→未选文件直接提交。**预期**：没有线索写入；不得提交A的残留；选新文件B后预览及提交对象均只属于B。

## REQ-LD-003 推送、侵权审核与归档

- 状态：部分确认（SD-13）＋待审核。来源：L-C04 L-D03 L-D04。字段组：LD05/LD06。
- 目标／动作与结果：推送符合条件的待推送线索至待审核；获授权客户可查看推送给本企业的线索并执行审核。侵权结论进入待确认，不侵权进入归档分支；不取证记录决定及归档信息。所有入口按当前状态和企业数据范围校验，不以按钮是否显示代替规则。
- 异常、边界及待决：运营内部审核、归档原因、重开／撤销／更正仍按BQ-03；客户只能处理本企业获授权线索。SD-07已确认无勾选不执行；批量模式、并发与重试由T02设计。
- 依赖：B03/B08/T02；正式操作者与客户企业范围统一受REQ-XM-001约束。相关批量、失败和重复控制见REQ-SH-004。
- AC-LD-003：**给定／操作**：已归档线索与待推送线索同时被选中并批量推送。**预期**：提交前明确指出不合法对象，整批不写；已归档线索不能经普通审核变为待确认；重开须走BQ-03最终批准的独立动作。

## REQ-LD-004 取证移交保留原线索

SD-02补充：允许一条只读来源线索关联多个公证事项，每次明确新建取证批次；对应AC-XM-003。SD-08进一步将批次载荷作为基线，撤销、更正权限转BQ-03。

- 状态：确认方向（BD-01）。来源：L-C03 L-C04 L-C05 L-D05 BD-01 FIX-14。字段组：LD04/LD05/LD06/NT01。
- 目标／动作与结果：线索取证确认成功后，原线索保留只读并关联公证记录；每个明确新建的批次记录所选商品、材料、公证处、取证方式、目的和当时来源快照。公证详情不得按同店铺猜配别条线索，来源缺失不能冒充无来源。
- 异常、边界及待决：误建批次的撤销、开始办理后的终止和原线索误录更正按BQ-03；材料留存按BQ-11；失败不得显示整项移交成功，事务及重试由T02设计。
- 依赖：B08/B21/T01/T02/T05；正式操作者与数据范围统一受REQ-XM-001约束。相关批量、失败和重复控制见REQ-SH-004。
- AC-LD-004：**给定／操作**：一条待确认线索含两商品和材料，明确选择其中一组建立批次N1，再选择另一组建立N2，并尝试普通编辑原线索。**预期**：原线索仍可查询且只读；N1/N2分别保存所选载荷并反查同一来源；普通重试不生成N3；撤销或更正按BQ-03结果执行。

# EV 证物与公证书

物品保管、纸质公证书和电子材料分别表达。四个证物状态与两个纸质证状态只作为候选，不作为任意互转的授权。

依据：[固定事实](../../../demo-reverse/v158/modules/M05-evidence.md)、[候选](../../../demo-reverse/v158/modules/M05-evidence-candidates.md)、[决定](../../../demo-reverse/v158/DECISIONS.md)和[纠偏](../../../demo-reverse/v158/CORRECTIONS.md)。字段见[领域模型](../DOMAIN.md)，B/T/E见[缺口](../GAPS.md)，通用技术设计见[TD-BASE-04](../TECHNICAL-DESIGN.md)。本模块TD-SLICE、API、实现、迁移及正式测试未产生；所有AC为未执行目标场景。

## REQ-EV-001 身份、来源与一致关联

- 状态：纠偏约束＋待审核。来源：E-C01 E-C04 FIX-11 FIX-18。字段组：EV01/MT01。
- 目标／动作与结果：证物具有稳定身份和明确来源关系，查看、筛选、编辑采用相同关联集合。来源说明与可编辑备注分开；缺名称或店铺不应崩溃或伪填，保留未知或明确校验错误。
- 异常、边界及待决：SD-25确认附件的90天恢复和引用文件版本作废，但证物业务记录、物理对象和附件删除不能混为一事；编号唯一范围、备注粒度、证物删除／销毁仍由B21决定；不同来源类型不混入一个无类型ID。
- 依赖：B21/T01/T02；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-EV-001：**给定／操作**：一件由公证转案产生的证物，按案件阶段筛选、查看、编辑；再新增缺名称的同组物品。**预期**：同一件的关联可一致定位；缺名称时无未定义变量异常或假名称，处理按批准字段规则；备注不覆盖真实来源。

## REQ-EV-002 公证书按记录处理

- 状态：待审核＋纠偏约束。来源：E-C02 FIX-18。字段组：EV02。
- 目标／动作与结果：公证书具有自身编号、出证资料及纸质状态；已有多本时必须明确操作对象，不默默只改第一本。出证资料更正与纸质件交付不是同一动作。
- 异常、边界及待决：是否按本作为正式管理粒度、一次多本、出证后改号和纸质状态B21；禁止据Demo首项.find裁定只能一本。
- 依赖：B21/T01/T02；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-EV-002：**给定／操作**：同一案件已有两本不同编号公证书，选择第二本修改获准的纸质状态。**预期**：第一本不被误改；操作及结果明确指向第二本；若批准整组操作，预览须列全部实际对象。

## REQ-EV-003 保管动作、留存与空台账

- 状态：部分确认（SD-21）＋纠偏约束。来源：E-C03 E-C04 FIX-23。字段组：EV01/EV02/EV03。
- 目标／动作与结果：按真实入库、移交或销毁动作维护保管事实；填编号／货架是否足以入库须业务决定，不补造签收记录。合法空台账保持为空，不回填演示物品。
- 异常、边界及待决：附件生命周期已定；证物签收／销毁凭据、角色、业务动作可逆范围和公证书管理粒度仍见B21；销毁不等于数据库删除；多条处理必须明确选择并共用业务校验（SD-07/08）。
- 依赖：B21/SD-07/08/25/T02/T05；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-EV-003：**给定／操作**：合法没有证物的业务环境刷新列表；另一件仅填写货架而没有接收凭据。**预期**：空列表保持空；不能显示模拟在库证物；第二件是否完成入库待B21决定，未确认前不自动断言已签收。

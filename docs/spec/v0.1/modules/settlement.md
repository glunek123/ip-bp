# ST 结算

案件应结算条件、一次发起、汇总账单、律师费发票和实际收付款分别建模。客户和律师两侧分别表达；SD-20已把公式后置，本阶段只设计数据字段，不能从Demo补造计算规则。

依据：[固定事实](../../../demo-reverse/v158/modules/M06-settlement.md)、[候选](../../../demo-reverse/v158/modules/M06-settlement-candidates.md)、[决定](../../../demo-reverse/v158/DECISIONS.md)和[纠偏](../../../demo-reverse/v158/CORRECTIONS.md)。字段见[领域模型](../DOMAIN.md)，B/T/E见[缺口](../GAPS.md)，通用技术设计见[TD-BASE-04](../TECHNICAL-DESIGN.md)。本模块TD-SLICE、API、实现、迁移及正式测试未产生；所有AC为未执行目标场景。

## REQ-ST-001 案件条件和计算

- 状态：确认方向（BD-08、SD-12/20）＋纠偏约束；公式明确暂缓。来源：S-C01 BD-08 FIX-16。字段组：ST01/CU05/CA10。
- 目标／动作与结果：案内编辑客户结算公式仅影响本案；客户协议另行维护。按明确客户关联取条件，不能误用权利主体或首客户兜底；显式0不能当缺失回退标的额，手调与自动计算来源要区分。
- 异常、边界及待决：SD-12确认案件沿用适用协议版本；SD-20要求先设计字段、暂缓结算基数、比例、公式和手调。SD-26只确定金额已知／待定和0元不发起，不批准Demo简单百分号解析或Math.round取整；重算不能悄悄替换已确认金额。
- 依赖：B19/T04/T06；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-ST-001：**给定／操作**：同客户案件A/B，客户协议70%；在A改为60%；另有结案额明确0、标的额1000的案件。**预期**：B与客户协议仍70%；A独立变更；明确0不回退1000。实际应结算数值须按B19批准公式验收。

## REQ-ST-002 发起与完成分离

- 状态：确认方向（BD-09、SD-13/20）；分次规则待审核。来源：S-C02 BD-09 FIX-20。字段组：ST02/ST04。
- 目标／动作与结果：运营可对已知且大于0的待提交金额发起律师结算／账单流程；待定或0元只保留业务记录，不生成发起。发起成功只标已发起，不标已结算，实际完成以财务结果为准。每次发起可追溯案件、侧别、金额、日期和主体。
- 异常、边界及待决：分次额度、余额占用和释放、提交时重校验B20/T02；不能把打开弹窗时余额当最终事实；部分完成映射须协议。
- 依赖：B19/B20/T02/T04/T06/E03；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-ST-002：**给定／操作**：案件应结算100，发起40，财务尚无结果。**预期**：展示已发起40且不显示完成40或实收40；剩余额度计算政策待B20；失败与实际结果另记录。

## REQ-ST-003 跨收付方账单与撤销

- 状态：确认方向（BD-07、SD-13/20）＋纠偏约束；撤销规则待审核。来源：S-C03 BD-07 FIX-19。字段组：ST02/ST03/ST05。
- 目标／动作与结果：允许跨收付方合单，但每条明细保存并展示真实收付方、来源行身份及金额。撤销或恢复应按稳定源行身份作用，不按当前数组位置恢复，不能用第一位收付方代表整单。
- 异常、边界及待决：运营发起律师账单、律师上传发票已定；何时允许撤销、是否释放发起占用、各方确认、发票更换和留存B20/21；不能由费用BD-06直接判定所有账单禁止撤销。
- 依赖：BQ-10/BQ-11/SD-07/08/T01/T02/T06；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-ST-003：**给定／操作**：选甲100与乙200两条同侧发起明细合单，随后重排列表；在获准状态执行撤销。**预期**：账单逐项为甲100、乙200且合计300；重排不改变源行映射；撤销只影响对应明细，余额释放结果待B20。

## REQ-ST-004 实际结果及统计核对

- 状态：待审核＋纠偏约束。来源：S-C04 FIX-20。字段组：ST04/CA11/CU08/RP01。
- 目标／动作与结果：实际回款／付款、开票和发起分别作为统计事实；案件、结算中心和客户详情同义指标使用同一已确认口径，不因月份去重漏明细，不把种子日期当完成证据。
- 异常、边界及待决：回执方向、部分、拒付、退款与对账B20/E03；统计口径B22；不虚构财务API或自动审批。
- 依赖：B20/B22/T06/E03；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-ST-004：**给定／操作**：同月两笔发起100与200，实际只收到第一笔中的40，查看三个页面。**预期**：应按一致获准口径反映两笔来源与实际40，不显示已收到300，也不因同月只显示首笔；具体状态由协议确定。

## REQ-ST-005 律师费发票材料

- 状态：确认方向（SD-13/21）；字段边界可设计，动作细则待审核。来源：BR-03 `业务审核!F9/F17`。字段组：ST05/MT01。
- 目标／动作与结果：运营发起律师账单后，获分派律师可在律师结算页上传该账单的律师费发票。发票材料必须关联明确账单或明细、律师、上传时刻和实际文件内容；上传发票不等于已付款、已完成或财务已接收。
- 异常、边界及待决：发票被账单引用后不得删除，只能上传新版本并将旧版作废；一单多律师／多张发票、允许格式和账单撤销后的处理仍由B20及切片设计决定；E02未定前不选择存储实现。
- 依赖：B20/T03/T05/T06/E02；所有操作者和数据范围受REQ-XM-001约束。
- AC-ST-005：**给定／操作**：运营发起律师账单，负责律师上传发票；另一律师尝试向不属于自己的账单上传；负责律师再替换已引用发票。**预期**：首张绑定正确账单且不改变付款状态；越权上传拒绝；替换产生新版本，旧版作废但仍可审计，不出现删除按钮。

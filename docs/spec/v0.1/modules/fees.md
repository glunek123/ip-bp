# FE 费用

费用录入／来源生成→发起→财务处理结果→必要的更正或冲销。后三者的完整状态及外部协议仍待确认；费用中心、案件明细和合并来源不是三套可独立改写的账。

依据：[固定事实](../../../demo-reverse/v158/modules/M04-fees.md)、[候选](../../../demo-reverse/v158/modules/M04-fees-candidates.md)、[决定](../../../demo-reverse/v158/DECISIONS.md)和[纠偏](../../../demo-reverse/v158/CORRECTIONS.md)。字段见[领域模型](../DOMAIN.md)，B/T/E见[缺口](../GAPS.md)，通用技术设计见[TD-BASE-04](../TECHNICAL-DESIGN.md)。本模块TD-SLICE、API、实现、迁移及正式测试未产生；所有AC为未执行目标场景。

## REQ-FE-001 原始费用和来源身份

- 状态：纠偏约束＋待审核。来源：F-C01 F-C03 FIX-11 FIX-15。字段组：FE01/FE02/NT06。
- 目标／动作与结果：维护明确来源、业务归属、费用类型、方向、金额状态、金额和日期，中心与明细为同一事实。已知金额非负且必填，待定不落假0；多次实际同类费用须能区分。选择器修改显示文本后须重新确认真实目标。
- 异常、边界及待决：0元费用保留记录但不生成支付指令；未转案公证费用归属／支付B11，类型、方向和收付方仍见B18；来源改动不得绕过REQ-FE-002。
- 依赖：B11/B18/T01/T02/T04；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-FE-001：**给定／操作**：案件A两次分别发生同类费用100和200；费用选择器先选A再改输入为B而不选候选。**预期**：不得把两次费用静默覆盖成一次；不得以显示B而保留隐藏A身份提交，须确认真实对象；是否两笔发起由获准费用规则决定。

## REQ-FE-002 已发起／已支付保护

- 状态：确认方向（BD-06）。来源：F-C02 F-C03 F-C05 BD-06 FIX-15。字段组：FE01/FE02。
- 目标／动作与结果：已发起或已支付费用禁止直接改金额或删除；适用于中心、案件、合并来源、业务字段重算和自动同步全部入口。变更走明确的更正或冲销关系，不保留已支付状态却覆写原金额。退款接收方与处理阶段分开。
- 异常、边界及待决：更正／冲销权限、审批、部分冲销、回执B18/E03；未发起费用的编辑范围仍待审核；不把费用保护扩大为已批准账单撤销规则。
- 依赖：B18/T02/T06/E03；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-FE-002：**给定／操作**：费用已支付100，从案件、公证来源重算、费用中心及合并来源分别尝试改成200或删除。**预期**：各入口均不能直接修改或删除原事实；保留原金额与状态，提示使用更正／冲销；后者具体流程未设计，不能假称可执行。

## REQ-FE-003 原支出和退款分别提交

- 状态：确认方向（BD-05）。来源：F-C04 BD-05 FIX-17。字段组：FE01/FE03。
- 目标／动作与结果：原样品支出和退款保留各自身份、金额及提交对象；净额仅用于展示。发起前列明所选原始记录与金额，不以净额行的首个ID替代全部费用。
- 异常、边界及待决：SD-15/26确认同一原支出的累计退款不得超过原支出且无超额审批；退款以正数和方向表达。退款对象、科目和净额显示范围仍待B11/18/E03；零净额不删除原始记录。
- 依赖：B17/B18/T06/E03；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-FE-003：**给定／操作**：样品支出100，先后退款30、60，再尝试退款11；另退款至累计100。**预期**：前两笔保留并展示净额10；第三笔因累计101被拒绝且无审批入口；累计100时净额0但全部原始记录仍可查。

## REQ-FE-004 发起、状态与财务结果

- 状态：待审核＋纠偏约束。来源：F-C02 FIX-15 FIX-20。字段组：FE01/FE02/ST04。
- 目标／动作与结果：按获准条件选取并确认费用发起；本地请求发起不等外部受理或已支付。处理阶段、开票及退款接收方分别表达；未知外部状态不可回退成未发起，失败与待核对须可辨认。
- 异常、边界及待决：未发起／已发起／已支付仅已知语义，不批准完整外部状态机；重试、防重复和结果核对T06/E03；批量必须明确选择并共用业务校验（SD-07/08）。
- 依赖：BQ-09/SD-07/08/T02/T06/E03；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-FE-004：**给定／操作**：发起费用后未获得外部结果，或收到无法识别的回执状态。**预期**：不显示已支付，不把未知结果改未发起并再次自动发送；实际失败恢复和回执映射等待协议，目标场景未联调。

## REQ-FE-005 转案与合并费用关联

- 状态：确认方向（BD-12）＋纠偏约束。来源：F-C01 F-C05 BD-12 FIX-17。字段组：FE01/NT06/CA12。
- 目标／动作与结果：公证转案完整关联所有原费用并保留来源，不重复生成；合并后的来源展示不得脱离同笔费用身份或绕过已处理费用保护。费用身份、原业务来源和当前展示归属分别表达。
- 异常、边界及待决：合并办理组只聚合展示，费用始终保留原业务来源；历史重复费用清理需单独审核，不自动改账；0元费用不生成支付指令。
- 依赖：B11/B18/T01/T02/T06；所有操作者和数据范围受REQ-XM-001约束，失败／批量／重复处理结合REQ-SH-004。
- AC-FE-005：**给定／操作**：公证事项有四类费用且一笔已发起，转案后把案件加入合并办理组再解除。**预期**：各处追溯同一费用及既有状态；合并／解除不复制、迁移或重发费用，不出现第二笔支付指令。

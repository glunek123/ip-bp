# 骨架复核与文档同步验收

日期：2026-09-15；任务 CTX-001。当前状态和后续工作见 [开发状态](project-status.md)。

## 范围结论

正式工程保持通用技术骨架范围，没有将 Demo 的业务方案提前固化。证据为 backend/src/app.module.ts 仅装配配置和健康模块；backend/prisma/schema.prisma 没有 model；正式源码只有健康接口、数据库连接和技术边界。测试中的 count DTO 与 contract-test Controller 是测试夹具，不进入应用。

页面中的系统名称和配色属于可替换品牌展示，不构成案件模型。后续把审核后的 Demo 反向整理为已确认需求后，业务可以沿现有模块边界增加，无需为了当前骨架另建一套工程。

这不是“所有未来需求都不会冲突”的承诺。公司登录、数据归属或部署限制等新事实仍可能要求调整基线；遇到真实冲突按架构变更规则处理。

## 本轮落实的上下文机制

- project-status.md 作为当前进度与恢复入口；AGENTS.md 要求开工、压缩恢复和中断恢复时读取。
- ai-coding.md 明确事实来源、检查点、文档更新顺序、历史报告适用边界，以及 Demo 观察到已确认需求的转换流程。
- context-memory.mjs 比对文件新增、修改、删除，检查状态文档必要章节和 Markdown 相对链接；任何差异都使 `context:check` 失败。
- 显式 `context:record` 只写文件指纹，不写状态或测试结论。受跟踪文件改变而状态未更新时拒绝记录；采用临时文件重命名保存快照。
- `pnpm verify` 将文件一致性、类型、Lint、格式、测试与构建串为本地交付入口。业务/E2E验证按改动风险追加。

检查范围为脚本中列出的源码/配置/文档文本扩展名及 Demo 文本资产；JSON 快照只含路径、归一化文本 SHA-256 和记录时间，排除自身、依赖、生成结果、运行产物、本地临时目录和真实 .env 文件。UTF-8 BOM 与 CRLF 归一化后计算哈希；二进制附件与图片不纳入此文本快照。

该机制发现机械漂移，不判断文字是否真实，也无法阻止用户绕过本地命令。语义核对仍由每次任务的执行者和必要审查承担。

## 验证记录

- 初始失败：最小检查器未实现时，12 项场景中 11 项失败；缺快照场景按预期报错。
- 功能实现后：12 项原生断言场景通过。交付测试统一使用已有 Vitest，保留相同断言，不引入另一套测试框架。
- 根包声明 Vitest 4.1.11 与 Vite 7.3.6，以便脚本测试使用已选工具且固定其 Vite peer；版本来自原清单，与前端共享安装。Node 内置文件/哈希 API 已足够，不引入同步服务或额外依赖。
- 当前工作区 `context:check` 已实际验证缺少首个快照时失败，不自动创建或标记完成。
- 完整复验：项目 Node 24.21.0 / pnpm 11.27.0 下 `pnpm verify` 退出码 0；文档一致性、类型、Lint、格式、12 项工具测试、9 项前端测试、17 项后端测试和前后端构建全部通过。
- 跨端复验：独立测试 PostgreSQL 启动健康，`pnpm test:e2e` 退出码 0，2 项 Chromium 测试通过，覆盖真实数据库健康链路、OpenAPI 和失败重试。
- 验证后仅补充文档结果与链接支持边界，再执行格式检查和快照一致性检查；最终文件范围由 context-snapshot.json 记录。

独立同步机制复核未发现当前交付阻断问题。链接检查只覆盖现有文档采用的无标题行内文件链接，不支持引用式、带标题链接及复杂 Markdown，也不检查锚点；已同步收窄规范承诺。

独立只读骨架审查与主代理源码核对一致：没有当前范围的架构阻断项；上表欠缺不应被遗漏，也不应提前扩为未批准业务实现。

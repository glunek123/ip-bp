# 运营测试环境配置与恢复准备

本页与 [UAT 配置模板](../../backend/.env.uat.example)交付单实例 Node 后端的配置准备，不代表环境已部署或可供人工验证。源码提供显式可选的 `PRIVATE_BLOB_STORAGE_DRIVER=local`，复用现有私有文件适配器；生产默认仍不可用，模板没有启用该选项。

编写基线：`bc3d9e3aa4e7e708f5471c91ec078af67dcfb915`。实际部署须绑定之后获准的完整提交和构建产物。本轮不创建环境、不连接数据库、不执行备份、迁移或恢复，不启用账号或赋予业务权限。人工测试账号增权按用户要求放在功能完成之后。

## 1. 独立资源与当前限制

| 对象           | UAT 要求                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据库         | 独立的 UAT 实例／持久存储、数据库和数据库角色，独立保存凭据。模板数据库名为 `dev_cor_uat`。                                                                     |
| 禁用目标       | 不使用人工 R2 的 `15438`、技术验收的 `15439`，也不使用现有 Compose 的 `dev_cor`／`dev_cor_test`、开发／测试卷或其同卷容器。换容器名称不能形成数据隔离。         |
| 私有文件       | 独立的绝对非公开路径／存储资源，不复用 `.local/private-files/test`、R2 文件或验收文件。不能置于前端静态目录，不能由代理直接公开下载。                           |
| 账号           | UAT 独立账号和授权记录；不搬用 H42、W/R、技术角色、会话或合成身份配置。本页不创建账号、密码或 Grant。                                                           |
| 浏览器入口     | 独立的 HTTPS 主机名。Cookie 不按端口隔离；同一主机名换端口不能隔离 UAT 与原环境的 Cookie。                                                                      |
| 宿主／访问方式 | 用户已确定在开发完成后自行租用服务器作为测试环境。具体 OS、HTTPS 域名、代理、真实目录和运维方式在部署前填写；不部署到当前电脑，不在本轮采购云资源或指定供应商。 |

现有 [compose.yaml](../../compose.yaml)只管理本地开发库和测试库；测试库使用 `tmpfs`。它不是运营部署文件，不能通过默认 `docker compose up` 当作 UAT。数据库 URL 的现有校验只检查格式，**不会阻止误填上述端口、数据库名或共享卷**；执行前仍须核对真实目标身份和资源归属。

### 当前代码行为与部署前提

- [MaterialModule](../../backend/src/modules/materials/material.module.ts)调用同一个[存储 provider](../../backend/src/modules/materials/private-blob-storage.provider.ts)。生产未设置 driver 时仍为 `UnavailablePrivateBlobStorage`；只有显式 `local` 并提供通过现有路径校验的私有根，才使用 `LocalPrivateBlobStorage`。不得把环境变量解析成功当作服务器目录、材料 HTTP 或部署验证通过，也不能降级为 `development` 绕过生产配置。
- [后端入口](../../backend/src/main.ts)固定监听 `127.0.0.1`，没有 `HOST` 配置。代理必须能到达该运行命名空间的回环地址；跨容器代理不能只靠发布端口假定可达。宿主方案若不适配此约束，需要另行评估源码变更。
- 后端启动会运行已有后台任务，例如[材料清理任务](../../backend/src/modules/materials/material-cleanup.service.ts)。启动服务不是只读操作，不能用“启动看看”代替部署批准。

### 已实现的默认关闭接线：独立 UAT 本地持久目录

本期限定单实例 Node 后端和独立本地私有持久目录，复用原有适配器，不新增 SDK、依赖或存储服务。服务器尚未配置，模板中的选择项仍为注释；没有修改真实环境文件。

- `PRIVATE_BLOB_STORAGE_DRIVER` 唯一可设置值为 `local`，未知值拒绝启动且不回显输入。未设置时保持全部旧行为：生产使用不可用适配器，开发／测试使用本地适配器。生产显式选择 local 而缺少私有根时，启动配置校验失败。
- 本地根必须为 UAT 独占、持久、源码树外的绝对非公开目录；禁止共用 R2／验收／开发／测试目录。现有环境校验只检查路径的词法范围，不能证明真实挂载、符号链接／重解析点及 ACL 安全；这些须在最终宿主上核验，不能靠配置解析宣称严格隔离。多实例各自保存一份本地目录的方案不能直接套用。
- 原 `MaterialService`、Controller、部门范围、文件签名／大小、不可变版本和引用约束保持不变，不能让前端直接访问目录，不新增批量清除或权限例外。
- [环境直接测试](../../backend/src/common/environment.spec.ts)覆盖显式选择、缺根、非法值和原路径拒绝；[provider 直接测试](../../backend/src/modules/materials/private-blob-storage.provider.spec.ts)从实际模块元数据调用工厂，并在新临时目录用小合成 PDF 验证 put／open／hash／delete 及穿越拒绝。测试没有启动 Nest、数据库或监听器。未改变或重跑整套原适配器算法验证；原鉴权实现没有变化，也未据此宣称真实材料接口或运营授权已验收。

边界依据是[技术设计第7节“T05：文件、上传草稿与OCR候选”](../spec/v0.1/TECHNICAL-DESIGN.md)：业务只依赖存储缝隙，具体服务商、加密、备份和恢复留给 E02；内部 MVP 允许用明确标注的测试／本地 Adapter 验证契约。[技术基线](../architecture.md)未批准生产存储服务商。本次限定 UAT 的接线不等于正式生产存储已完成，不承诺 NAS、多副本或对象存储能力。

## 2. 模板字段与真实代码契约

变量以 [validateEnvironment](../../backend/src/common/environment.ts)及实际使用点为准。不把未实现的 `APP_URL` 或 Cookie 开关当作支持的配置。

| 变量                          | 填写要求与实际作用                                                                                                                                                                                       |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`                    | UAT 模板使用 `production`；代码仅接受 `development`、`test`、`production`，不接受 `uat`。该模式启用 Secure Cookie，且不开放开发 Swagger。                                                                |
| `PORT`                        | 必填，1–65535 的十进制整数。只决定后端回环监听端口，不分配外部 HTTPS 端口。由宿主方案填写，避免占用既有服务端口。                                                                                        |
| `DATABASE_URL`                | 必填，`postgresql://` 或 `postgres://` URL。替换全部占位项；用户名／密码中的特殊字符须 URL 编码。使用 UAT 专用角色和数据库，连接加密／证书参数按最终宿主与数据库方案确定，不能通过关闭证书验证消除报错。 |
| `AUTH_THROTTLE_SECRET`        | 必填，至少 32 个随机字节的十六进制编码，即至少 64 个十六进制字符。由获准的密钥管理方式生成并注入，UAT 独用。代码检查格式，不验证随机性。不得提交实值或使用示例固定串。                                   |
| `TRUST_PROXY_HOPS`            | 0–10 的整数；代码缺省为0，模板要求显式填写。只按真实受信代理跳数设置，不能为使登录通过而任意增大。                                                                                                       |
| `PRIVATE_FILE_ROOT`           | 模板要求预留独立绝对路径。生产未选 driver 时可以省略；显式 local 时必填并经过原路径校验。源码目录和公开目录不能作私有根。实际创建、挂载及 ACL 命令在服务器确定后提供，当前不执行。                       |
| `PRIVATE_BLOB_STORAGE_DRIVER` | 可选，仅接受 `local`；模板仅注释说明，不启用。生产默认不可用，显式 local 配合合法根才接原本地适配器；开发／测试原默认行为不变。                                                                          |

不配置 `E2E_IDENTITY_FIXTURES`：生产模式明确拒绝该变量。数据库 URL、节流密钥、密码不得进入任何前端 `VITE_*` 变量、构建日志或公开配置。

[ConfigModule](../../backend/src/app.module.ts)设置了 `ignoreEnvFile: true`，不会自动寻找 `.env.uat`。Node `--env-file` 或宿主密钥注入必须在进程启动前提供实际变量。现有 `pnpm start` 读取的是后端 `.env`，不能直接假定它使用本模板。

模板故意保留不能运行的 `REPLACE_*` 值。实际配置保存在源码树外的受保护位置或密钥存储；不要覆盖开发 `.env`，也不要把实值写回 `.env.uat.example`。

## 3. HTTPS、代理与同源认证

[认证控制器](../../backend/src/auth/auth.controller.ts)及 [Cookie 实现](../../backend/src/auth/cookie.ts)决定以下行为：

- 生产会话 Cookie 为 `dev_cor_session`，带 `HttpOnly; SameSite=Lax; Path=/; Secure`；CSRF Cookie 为 `dev_cor_csrf`，可供前端读取，同样带 `SameSite=Lax; Path=/; Secure`。有效期为12小时；没有可配置的 Cookie 名称或 Domain 开关。
- 前端通过相对路径 `/api/v1` 请求后端。HTTPS 入口须同源提供前端和 API；不能把另一域 API 地址当作已实现的跨域部署能力。
- 登录检查浏览器 `Origin` 的主机／端口与 `Host` 相等，协议与 `request.protocol` 相等。TLS 若在代理终止，代理须保留外部 `Host`，清除客户端伪造的转发头，并按真实链重建 `X-Forwarded-Proto` 等信息；`TRUST_PROXY_HOPS` 必须与该链一致。
- 后端回环端口不能作为绕过代理的公开入口。不要把所有来源都当成可信代理；错误的代理配置还会影响登录节流使用的来源 IP。
- Cookie 会话的写请求需要 `X-CSRF-Token`；不关闭 CSRF、不通过合成身份或伪造转发头绕过登录。代理应正确透传 Cookie、Set-Cookie 和所需请求头。

代理配置语法、证书部署、进程启动／停止和防火墙命令均在后续租用服务器、明确 OS 与访问方式后提供；不因此阻塞当前离线代码交付，本页不新建部署框架。

- 后端、前端、Prisma 生成物、迁移目录必须来自同一获准提交，安装使用冻结锁文件。不能复制某个 worktree 的旧 `dist` 或连接验收库补构建。

4. 完成下面的备份／恢复准备，单独批准目标迁移和发布范围后，才由指定执行者部署。迁移走现有 Prisma Migrate 正式入口，不运行 `migrate dev`、reset、种子脚本或技术验收夹具。

## 5. 最小备份与恢复操作说明

### 备份：数据库、私有文件、版本属于同一恢复点

1. 为获准的 UAT 备份分配唯一 `BACKUP_ID`，记录 UTC 时间窗、目标身份及责任人。先核对实际端点，排除 R2、技术验收和开发／测试目标。
2. 通过待定宿主的进程管理方式停止全部 UAT 后端实例及其后台任务，阻止其他写入和迁移。在数据库和文件备份都结束前保持该写入静止窗口；仅阻止浏览器按钮或只执行 `pg_dump` 不能保证 DB／文件一致。
3. 使用受保护的连接服务配置和同主版本 PostgreSQL 工具导出数据库。保留所有者／ACL 信息；不在参数、日志或文档写入口令。下面的 `service` 必须预先绑定到批准的 UAT 目标，未配置时不得回退到本机默认库。

   ```text
   # 未来获批后才执行；工具路径、服务文件和输出位置待宿主确定。
   pg_dump --format=custom --file="<BACKUP_DIR>/<BACKUP_ID>/database.dump" --dbname="service=<UAT_BACKUP_SERVICE>"
   ```

4. 使用宿主批准的备份工具完整保存 UAT 私有文件根，保留相对路径、字节及恢复所需权限信息；不把整个源码目录或开发卷当作附件备份。归档命令待宿主确定。
5. 将数据库导出、私有文件包及恢复清单绑定到同一个 `BACKUP_ID`。清单记录：提交／tree、前后端构建与锁文件 SHA256、Node／pnpm／PG 版本、实际迁移账本及 checksum、导出与文件包 SHA256、文件相对路径／大小／SHA256、静止窗口和结果。另行保护数据库角色／所有权恢复资料及密钥引用；公开清单不保存密码、Cookie、令牌或密钥实值。
6. 备份和文件清单都成功后才按批准步骤恢复 UAT 服务。任何一部分失败则将该恢复点标为不可用，保留失败证据。备份介质须受限访问并加密；保存位置、保留时长和恢复目标指标随宿主运维方案确定，不擅自承诺 RPO／RTO。

不要在运行中的数据库数据目录上直接复制文件充当逻辑备份。备份包含账号、会话及业务材料，不能放进 Git、静态网站或普通共享下载目录。

### 恢复：先恢复到新的隔离副本

1. 单独批准恢复目标。在新的隔离 UAT 恢复实例／空数据库和新的私有文件根操作，不覆盖当前 UAT、R2、技术验收或开发／测试库。
2. 核对备份清单和文件 hash，准备匹配的 PG 版本、所需数据库角色／扩展及批准代码／构建。保留 dump 的所有权与 ACL 要求；不能为使 restore 通过而忽略权限错误。
3. 保持恢复副本无外部访问且不启动应用，使用批准的恢复连接服务导入。以下命令未执行；实际服务文件、权限、磁盘容量和工具路径待宿主确定。

   ```text
   pg_restore --exit-on-error --single-transaction --dbname="service=<NEW_ISOLATED_UAT_RESTORE_SERVICE>" "<BACKUP_DIR>/<BACKUP_ID>/database.dump"
   ```

4. 将同一 `BACKUP_ID` 的私有文件包恢复到新根，保持相对路径，按清单核对数量、字节和 SHA256。数据库已恢复但文件缺失时不能宣布恢复成功。
5. 对照迁移账本、候选版本、所有权／ACL、数据库约束与文件精确引用；不直接追加迁移“试着修复”版本不匹配。恢复会话／账号的处置须另行核准，不能自动向外开放旧 Cookie 或搬用技术账号。
6. 在恢复副本完成显式存储配置并获准验证后，启动隔离恢复副本，核对有权读取、材料下载及跨部门拒绝。记录实际恢复结果和耗时；通过前不切换原 UAT 入口，不宣称恢复演练完成。

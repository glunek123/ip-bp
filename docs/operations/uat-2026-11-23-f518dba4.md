# 2026-11-23 下午：案件详情指派律师入口（已部署 f518dba4）

## 需求来源

律师结算必须先有承办律师（`463376a0`：`LAWYER_REQUIRED_FOR_SETTLEMENT`）。测试环境大量案件没有指派，而列表页只有勾选后的批量入口与「变更承办律师」，详情页在匹配阶段之后没有任何补指派位置。

## 改动

| 位置                                | 改动                                                                                                                                         |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `case-lawyer-assignment.service.ts` | 首次指派推进版本时不再写死 `stage: 'PENDING_MATCH'`，改按 `LAWYER_ASSIGNABLE_STAGES` 集合校验，与事务上方 `isLawyerAssignableStage` 判定一致 |
| `CaseDetailPage.vue`                | 详情页按服务端 `capability` 决定是否渲染顶栏入口；打开抽屉里的指派面板；成功后关闭抽屉、提示并刷新详情                                       |
| `CaseLawyerReassignPanel.vue`       | 新增 `mode: 'assign' \| 'reassign'`，指派模式标题为「指派承办律师」、提交按钮为「确认指派」，变更模式行为与文案不变                          |
| `case-workspace-actions.ts`         | `primaryCaseAction` 过滤掉 `assign-lawyer`，指派入口不参与主办理按钮竞争                                                                     |

入口只在 `WAITING_COMPLAINT` / `WAITING_COMPLAINT_CONFIRMATION` 且内部账号、`GET /cases/:id/lawyer-assignment/capability` 返回 `canAssign: true` 时出现；文案按本案是否有承办律师切换「指派律师」／「变更承办律师」。提交沿用 `POST /cases/:id/lawyer-assignment`（`expectedVersion` + 幂等键），指派不推进案件阶段。

`PENDING_MATCH` 仍走原「匹配律师」表单：那里同时落结算约定，单独指派会让后续匹配跳过 `settlementMode` 写入，本轮不放宽。

## 关键约束

- 正式立案后仍锁定指派：`LAWYER_ASSIGNABLE_STAGES` 只有 `PENDING_MATCH`、`WAITING_COMPLAINT`、`WAITING_COMPLAINT_CONFIRMATION`。
- 无 `case.lawyer.assign`、非本案负责人且无部门代理的账号，`capability` 返回 403，前端不渲染入口。
- 幂等键沿用原面板逻辑：同一律师重试复用原键，换人换键。

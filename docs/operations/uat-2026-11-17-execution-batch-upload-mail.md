## 批量上传执行文书

| 步骤   | 实现                                                                                                                                    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 打开   | 列出所选案件，逐案 `GET /cases/:id` 预热（阶段、版本、轮次）                                                                            |
| 挂文件 | 每案一个文件选择器，PDF / 图片                                                                                                          |
| 提交   | 逐案 `uploadMaterialFile`（category `EXECUTION_APPLICATION`）→ `POST /cases/:id/execution-submissions`                                  |
| 入参   | 与单案面板同源推导：`trialRoundId`、`judgmentNextStepId`、`secondInstanceResultId`、`expectedSubmissionId`；重新提交时带 `changeReason` |
| 结果   | 逐案状态（提交中/已提交/失败），底部汇总「成功 N 件，失败 M 件」并列出失败案号                                                          |

## 批量邮寄

**模型说明**：系统邮寄入参是 `mailedAt` + `mailReceiptContentVersionIds`，**没有快递单号字段** —— 快递单通过邮寄凭证（照片/PDF，category `MAIL_RECEIPT`）体现。所以交互为「统一邮寄日期 + 逐案上传凭证」，不是填单号。

线上 UI 验收：

| 检查         | 结果                   |
| ------------ | ---------------------- |
| 弹窗标题     | 批量邮寄执行文书       |
| 邮寄日期     | 默认今天（2026-11-17） |
| 未挂凭证     | 提交禁用               |
| 列出所选案件 | 2 件，阶段显示中文     |
| 凭证类型     | 接受图片与 PDF         |

未做真实提交：邮寄会把案件推进到「待申请执行」且无撤销入口，留给业务方在真实案件上执行。

## 已知限制

1. 批量提交为**串行逐案**，20 案约需数十秒，期间不可中断（关闭按钮禁用）
2. 单案失败不影响其余案件，失败原因显示在该案行内
3. 邮寄前置条件为「已确认执行材料」，未确认的案件提交时会提示「该案尚未确认执行材料」

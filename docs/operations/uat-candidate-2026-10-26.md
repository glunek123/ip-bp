# 2026-10-26 测试环境版本交接

本页交接本地代码与构建候选。用户已有云端测试环境；本任务未连接或更改服务器。仿真数据由测试环境的另一个开发任务直接在该系统准备，本包没有数据导入脚本或账号密码。

## 包含的变更

- 运营列表、详情、办理侧栏和导出使用中文业务名称，接口与数据库业务编码保留。
- 侧栏统一表单分组、间距、卡片、材料区域和操作布局；系统名称统一为“知产案管系统”。
- 新建客户支持完整主体、负责运营与合作信息；统一称“合作协议”，文件可后补。客户、初始协议及初始运营同事务保存；结算条件仅保存约定文字，不计算金额或自动准入。
- 角色模板增加“选择全部内部权限”：选择完整权限目录中每项动作允许的最高范围，包含客户准入、结算、费用和人员权限管理；选择不会自动保存。

## 一个运营账号配置完整内部权限

系统不要求“准入主管”专用账号。部署任务使用已有获准管理账号，在“人员与权限”中复制角色模板，命名为“全权限运营”，点击“选择全部内部权限”后保存，再把该角色分配给指定的内部运营账号。若该运营账号已有完整角色，无需再建账号或重复赋权。

保存和分配仍由后端检查管理者的授权上限；不能通过快捷选择授予管理者自己没有的能力。全权限只指当前部门的内部权限目录，各动作仍遵守允许范围和业务阶段要求。例如限定本人办理的案件动作不会因全选变成任意案件写入。测试环境任务应把需要该运营办理的仿真任务按现有规则分配给该账号。客户、律师或公证机构的专属身份确认保留原身份规则，不把外部动作混入内部角色。

已有账号使用现有人员／角色管理界面维护。`auth:bootstrap-local`仅用于尚无本地账号的首次引导，不能用于给现有运营账号增权；不要在已部署环境重复初始化。

## 部署顺序

1. 核对交付包的版本清单与SHA-256，并保留现有应用版本。使用Node24.21.0、pnpm11.27.0；具体依赖锁定于`pnpm-lock.yaml`。在新版本目录安装依赖：`pnpm install --frozen-lockfile`。依赖按服务器平台安装，包内不携带开发电脑的`node_modules`。
2. 沿用服务器现有受保护的测试环境配置与独立私有文件根，不复制开发电脑`.env`，也不把配置文件放进前端静态目录。[UAT环境说明](uat-environment.md)列出了实际配置项、同源HTTPS和代理要求。
3. 先按现有运维流程备份数据库与私有文件，再在本包`backend`目录用服务器受保护配置运行：`node --env-file="<PROTECTED_UAT_ENV_FILE>" node_modules/prisma/build/index.js migrate deploy`。本版共有178个迁移，新增`20261026090000_customer_agreement_settlement_formula`，只加可空文字字段及约束。数据库已部署的旧迁移必须与包内checksum一致；不执行reset或migrate dev。
4. 前端入口使用本包`frontend/dist`；后端在本包`backend`目录运行：`node --env-file="<PROTECTED_UAT_ENV_FILE>" dist/main.js`。如服务器需要重新构建，先从同一源码执行`pnpm prepare:prisma`、`pnpm build:prepared`，不要混用不同候选的前后端产物。后端仍监听`127.0.0.1`，反向代理须同源提供前端和`/api/v1`。
5. 验证页面版本、登录、当前部门、角色配置、新建客户保存和刷新、合作协议后补文件、既有案件／公证／结算读取及跨部门拒绝。账号权限和仿真流程的实际验收由测试环境任务完成；本地检查不能替代这一步。

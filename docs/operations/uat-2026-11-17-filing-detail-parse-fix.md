# 2026-11-17 执行立案抽屉「资料加载失败」根因与修复

| 项目     | 值                                                                               |
| -------- | -------------------------------------------------------------------------------- |
| 修复候选 | `ebef0274`（解析根因）、`bf0b38e8`（选择器改版）、`8583ee66`（说明文案）         |
| 现象     | 案件 `00120261026015` 打开「执行立案」抽屉报「资料加载失败，请重试」，面板不渲染 |

## 根因

前端详情校验里，**记录更正契约**对邮寄记录要求「至少 1 个凭证文件」：

```ts
executionMailings: {
  fields: ['mailedAt', 'mailReceiptContentVersionIds'],
  files: 'mailReceiptContentVersionIds',
  minimum: 1,   // ← 旧规则
}
```

邮寄改为「备注 + 凭证选填」后，这条记录是 0 个凭证，`validRecordEdits` 判定失败 → 整份详情被判为无效（`INVALID_RESPONSE`）→ 抽屉只剩「资料加载失败」。

**注意**：这不是「待申请执行」阶段的问题，任何 0 凭证的邮寄记录都会让该案详情打不开。上一轮改邮寄时未做真实提交，所以没有暴露。

## 定位方法

1. 把线上真实详情 JSON 存到 `.local/qa/detail-keys.json`
2. 写临时 spec 用 mock fetch 跑 `getCase`，本地复现 `INVALID_RESPONSE`
3. 给 `validCaseDetail` 的 `return` 按顶层 `&&` 自动插桩（62 段），日志输出第一个失败段
4. 命中第 44 段 `validRecordEdits(...)`，逐层追到 `sectionRecordContracts.executionMailings.minimum`

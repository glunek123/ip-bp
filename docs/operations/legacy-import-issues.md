# 旧库导入：严重问题记录与修复（2026-11-25）

## P0：全部导入案件详情页空白

| 项 | 内容 |
| --- | --- |
| 现象 | 2,220 条导入案件接口 200，但页面显示「案件暂时无法读取」 |
| 影响 | 全部导入案件不可用（列表能看，点进去空白） |
| 根因 | 历史回填入口 `known` 里多写了 `legacyId`、`legacyCaseNumber` 两个自定义字段；前端 `validOrigin` 对 `known` 做**精确键集合校验**，多一个键即解析失败 |
| 定位 | 拆分 `validCaseDetail` 的 62 个条件逐条断言 → 失败点 `validOrigin` |
| 修复 | `known` 恢复为约定 9 键；旧 id 只写 `business_number_aliases` |
| 提交 | `3b1e495c` |
| 复验 | 2,220/2,220 接口 200；5/5 页面渲染正常（`编辑资料` 按钮存在） |

## P1：`case.version` 与事实版本不一致 → 404「案件归档来源不完整」

| 项 | 内容 |
| --- | --- |
| 根因 | 统一写 `version = 7`，但待归档案件最后事实是结案（toVersion 6）；`case-read.service.ts:1922` 要求 `closure.toVersion === case.version`（无归档时） |
| 修复 | 按事实链计算：受理 2 / 判决 3 / 执行 4 / 结束 5 / 结案 6 / 归档 7 / 无事实 1 |
| 复验 | 结案版本与案件版本不一致 0 条（归档案件除外，归档版本=7）、归档版本不一致 0 条 |

## P1：归档/结案建早了

| 项 | 内容 |
| --- | --- |
| 根因 | 用「有结案金额或归档日期」判断，导致判决中、执行中的案件也挂了归档记录 |
| 修复 | 结案只对 `WAITING_ARCHIVE`/`ARCHIVED` 建；归档只对 `ARCHIVED` 建 |

## P2：三类非空约束

| 约束 | 处理 |
| --- | --- |
| `fee_records.fee_date` 非空 | 用受理/归档/创建日期兜底 |

| `case_acceptances.court_case_no` 非空 | 无案号写「待补充-<旧id>」 |
| `case_acceptances.trial_round_id` 非空 | 每案建 1 个最小庭审轮次 |

## 业务规则

- A 只能把**自己负责**的案件移交出去
- A 不能动别人负责的案件（管理改派已移除）
- 交错了就找 B，由 B（新负责人）把案件交回来

## 代码改动

| 项                                        | 改动                                                                                        |
| ----------------------------------------- | ------------------------------------------------------------------------------------------- |
| `POST /cases/:id/responsible-user/assign` | 已删除                                                                                      |
| `recordEdits.canAssignResponsible`        | 已删除                                                                                      |
| 前端「管理改派」按钮                      | 已删除                                                                                      |
| `lockAndAuthorize`                        | 新增 `allowResponsible`：负责人本人始终可以操作自己负责的案件，不再要求 `case.routine.edit` |

最后一条是关键：原先移交要求 `case.routine.edit`，而接收方未必有这个权限，会导致「收到案件却交不回去」。现在负责人身份本身就是凭据。

## 配置修复

`UAT准入主管`、`UAT品维运营` 角色原先没有 `case.read`，收到案件后连详情都打不开（403）。已补 `case.read`（DEPARTMENT）。

说明：案件详情的入口校验要求 department 范围的 `case.read`，SELF 范围不满足。

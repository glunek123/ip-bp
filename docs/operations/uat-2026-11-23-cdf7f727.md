# 2026-11-23 线索详情页卡内编辑（已部署 cdf7f727）

## 需求来源

运营在测试环境截图标注三处：

1. 顶部「编辑线索」入口可删除。
2. 基础信息卡「编辑」有问题，改为在卡片内直接编辑。
3. 商品信息卡需要一个「新增商品」按钮。

## 改动

| 位置                             | 改动                                                                                                                |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `LeadDetailPage.vue`             | 删除顶部 `edit-lead` 链接；基础信息卡「编辑」改为卡内全字段表单；商品卡新增「新增商品」与「编辑」两个入口           |
| `LeadFactsEditor.vue`（新增）    | 卡内编辑案件类型／来源／平台／线索发现日期／店铺名／店铺 ID／侵权类型／披露标记／备注；客户、权利主体、运营为只读行 |
| `LeadProductsEditor.vue`（新增） | 商品行内增删与编辑（名称／链接／销量／单价／评论数），最多 100 行，至少保留 1 行                                    |

数据通路不变：具备 `capabilities.edit` 时用 `PATCH /leads/:id`，整包提交并回传现有 `products` 与 `leadScreenshotContentVersionIds`；只有 `routineEdit` 时仍走 `PATCH /leads/:id/routine-profile` 窄通道（店铺名、备注、已有商品），行为与改前一致。

`/leads/:id/edit` 路由与工作流抽屉的「编辑线索资料（不推进阶段）」入口保留，本次只删详情页头部入口。

## 关键约束

`lead.service.ts` 的商品校验为「全有或全无」：全部商品无 `id` 时数量必须与现有相等；部分商品无 `id` 直接 409。因此新增商品必须由前端生成 UUIDv4 一并提交，已存在商品保留原 `id` 并原样回传截图版本 ID，避免保存时清空关联。

`canEdit` 仍为「状态 `WAITING_PUSH` + `lead.edit` 授权」，已推送／已归档线索继续只能改店铺名、备注与已有商品，本批未放宽该业务规则。

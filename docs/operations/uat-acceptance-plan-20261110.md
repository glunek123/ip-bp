# 线上逐节验收方案（e61b2443）

> 对象：`https://111.231.164.248`（`current` → `releases/e61b2443`，295 项迁移）。
> 依据：[上线验收标准](../operations/release-readiness.md)。本方案只解决"怎么在已部署环境上逐节验收并留证"，不替代业务 Spec。

## 一、原则

1. **只增不改**：验收只新建数据，不动线上既有 21 个案件、37 条线索、4 个客户的任何字段；需要修改时只改自己新建的对象。
2. **可追溯**：所有新建对象的名称/原因/备注统一带 `上线验收-20261110` 前缀，便于事后识别与清理。
3. **失败即停**：某一节返回非预期状态码或状态机不推进，立即停止后续节点，保存请求与响应，转问题单；不在同一对象上重复试。
4. **一节点一证据**：每节记录 `状态码 + 阶段前后 + 版本号 + 关键字段 + 截图`，写入 `docs/operations/uat-acceptance-20261110.md`。
5. **不做破坏性验证**：不测删除、不作废真实案件、不触发历史数据回填。

| 用途       | 对象                                                                               | 命名                                                |

## 四、执行方式

- 脚本：`.local/qa/online/*.mjs`（Playwright，`ignoreHTTPSErrors`），按 B1→B14 顺序跑；每节输出一行 JSON 记录追加到 `.local/qa/online/acceptance-e61b2443.jsonl`。
- 人工介入点：B4（律师账号确认）、C2（需要两个浏览器上下文同时操作）、D1/D2（独立案件）。
- 任一节失败：脚本停止，打印失败节的请求体/响应体，人工判断是否为环境问题后再决定是否重跑该节（同一对象最多重跑 1 次）。

## 五、通过标准

对应 release-readiness 第五节七条放行条件，线上部分需满足：

1. A 组 7 项全绿；
2. B 组 14 节全部 201 且阶段/版本符合预期；
3. C 组 7 项行为符合预期（拒绝路径不产生写入）；
4. D 组 2 条分支各 201 且阶段正确；
5. 全程无非预期 5xx；
6. 结束后核对：既有 21 个案件版本未变，新增案件数=验收建案数。

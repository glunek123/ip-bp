# 运营试用说明

更新日期：2026-10-23。核对基线：`bc3d9e3aa4e7e708f5471c91ec078af67dcfb915`。

本说明用于本期内部运营MVP试用。功能已有代码和部分隔离技术验收；试用地址、人工账号及权限尚未交付，不能据此认定已部署或已完成运营人工验收。

## 1. 开始前

由交付负责人补齐以下信息，再通知运营开始试用。

| 项目               | 待填写内容                                       |
| ------------------ | ------------------------------------------------ |
| 试用地址           | 【待确认的UAT地址】                              |
| 人工账号           | 【负责人单独发放的内部运营账号】                 |
| 试用部门           | 【待确认】                                       |
| 试用数据           | 【允许查看、修改和导出的样本编号】               |
| 已批准的操作及范围 | 【只读／指定样本办理；本人／部门；是否允许导出】 |
| 问题反馈接收人     | 【姓名或反馈渠道】                               |

账号口令通过负责人指定的方式单独发放，不填入本文。隔离技术验收中的合成身份不是人工试用账号。人工测试账号增权在功能开发完成后另行安排，本文不执行或承诺增权。

1. 打开试用地址的 `/login`，输入“用户名”和“密码”。
2. 如出现部门选择，选择负责人指定的部门后登录。
3. 核对当前部门和侧栏入口。先用已批准的样本做只读查看，再进行明确允许的提交。

## 2. 入口速查

路径均相对于负责人发放的试用地址。入口和操作按实际权限显示；Demo是业务参考，正式系统以当前页面为准。

| 工作       | 正式入口                          | 最短查看路径                                                                   |
| ---------- | --------------------------------- | ------------------------------------------------------------------------------ |
| 客户       | `/customers`，页面“客户管理”      | 打开客户详情，查看“客户资料”“联系人与权利人”等内容；合作与负责运营信息常驻显示 |
| 线索       | `/leads`，页面“线索库”            | 按现有条件找到样本，打开线索详情，核对状态、客户和来源信息                     |
| 公证办理   | `/notary-matters`，页面“公证阶段” | 选择阶段，点击事项“查看”，核对来源线索和当前办理信息                           |
| 案件       | `/cases`，页面“案件”              | 选择“我负责”或“本部门全部”，填写筛选条件后点“查询”，再进入案件详情             |
| 结算与费用 | `/settlements`，页面“结算中心”    | 选择有权使用的“客户结算”“律师结算”或“费用中心”，查看明细和账单                 |
| 证物       | `/evidence`，页面“证物管理”       | 按案件进展等条件找到样本，查看证物与公证书信息                                 |
| 数据汇总   | `/reports`，页面“数据报表”        | 核对“本人负责”或“本部门全部”范围，查看统计；有独立导出资格时使用“导出报表”     |
| 辅助日程   | `/calendar`，页面“日历”           | 查看当前有权读取的日程；本说明不把日历另算为新增业务流程                       |

上述入口覆盖Demo对应的核心业务工作及报表汇总。结算、费用和证物已有实现，不属于等待从零开发的占位模块。

## 3. 最短核心操作

### 先完成一轮只读查看

1. 在“客户管理”打开指定客户，核对资料、联系人与权利人和合作信息。
2. 在“线索库”及“公证阶段”打开关联样本，核对来源与当前状态。
3. 在“案件”选择负责人批准的范围，点“查询”后进入详情，核对阶段、材料和办理历史。
4. 在“结算中心”及“证物管理”核对同一批样本。发起金额、账单和财务实际结果是不同信息；未接入财务回填时，实际收付及日期可显示待定。
5. 在“数据报表”核对当前范围和统计口径。不要把空范围的“暂无数据”当作读取失败，也不要把错误提示当作零记录。

### 需要验证提交时

仅对负责人明确批准的样本操作。操作按钮取决于当前环节和权限，不要求一个运营账号代替客户、公证处或律师完成各方确认。

1. 新客户从“新建客户”建立草稿，再按详情中可用的办理入口补全资料；草稿不等于已准入合作客户。
2. 新线索从“新建线索”填写页面必填信息。已有线索的推送、审核及后续取证按当前状态和实际参与方分别办理；未获批准时不要用“批量推送”试改多条数据。
3. 公证事项和案件打开详情后，按当前环节提供的操作填写真实信息、上传指定样本材料，再核对并提交。阶段、材料或版本不满足条件时，记录提示，不跳过前置步骤。
4. 经批准使用外部案件录入时，入口为 `/cases/external-entry`，按实际当前状态填写，提交按钮是“保存真实当前状态”；直接录入已归档案件另需授权。
5. 结算需要组成账单时，在允许的明细中勾选后使用“合并生成账单”；证物需要改状态时，核对勾选范围再使用“批量更改状态”。这两项都会改变数据，不能作为只读点击检查。
6. 提交后核对页面返回的记录与状态。出现“结果未知”或原请求待确认时，保留现场，使用页面已有的原请求核对／恢复入口或反馈给负责人，不换一份新请求重复提交。

## 4. 报表范围与导出

SELF表示本人负责范围；DEPARTMENT表示本部门范围。普通运营按本期普通运营配置使用SELF金额范围，部门金额需要额外批准。既有账号不会因本次代码交付自动获得任何新权限。

| 资格                       | 页面上的含义                                                                 |
| -------------------------- | ---------------------------------------------------------------------------- |
| 案件读取资格               | 能进入案件范围，不自动等于能读取报表金额；报表还会核对金额权限               |
| “查看报表金额”SELF         | 可读“本人负责”；不因此开放部门全部金额                                       |
| “查看报表金额”DEPARTMENT   | 可读相应部门范围；页面按后端返回的可用范围显示选择项                         |
| “导出报表”SELF／DEPARTMENT | 独立于金额读取授权，还要同时满足对应金额范围和客户、线索等汇总来源的读取资格 |

维护者核对权限时，对应字段为 `report.amount.read` 与 `report.export`，两者分别授权。只开放读取可以查看报表而不能导出；案件清单的“导出当前筛选结果”也是另一项能力，不能代替报表导出授权。

1. 打开“数据报表”，先核对统计范围。
2. 查看案件总数、进行中／已归档、案件类型／平台／法院分布、累计标的额、未知金额数量、金额区间及已归档案件平均标的额。
3. “结案率”的当前口径是已归档案件数除以全部案件数，不代表胜诉率或回款率。已知0元计入金额统计，未知金额不按0元计算；无已知归档金额时，均值不可用。
4. 有导出资格时点击“导出报表”，确认浏览器实际下载CSV，再核对范围。CSV为三列汇总“维度／项目／数值”，不是逐案明细或附件包；客户总数和公证在办数量属于CSV汇总项，本期不承诺独立统计卡片。

## 5. 没有权限或遇到错误时

| 可见情况                                 | 运营应做什么                                                                                  |
| ---------------------------------------- | --------------------------------------------------------------------------------------------- |
| 侧栏无入口、按钮不可用或范围选项缺失     | 先核对部门和已批准范围，交负责人核对权限；直接输入路径不会增加权限                            |
| 出现无权访问或403提示                    | 记录发生的操作和范围，不自行切换他人账号或要求临时扩大权限                                    |
| 登录失效或要求重新登录                   | 记录未确认的提交状态，再按页面提示重新登录；不要把未确认提交当成失败后重做                    |
| 页面提示读取失败、导出失败或请求结果未知 | 保留提示和时间，按下表反馈；导出以实际生成下载文件为成功，点击按钮或响应200都不单独证明已下载 |

反馈时填写以下最小信息，不附密码、Cookie、CSRF令牌、完整请求头或未脱敏业务材料。

| 信息       | 示例格式                                                 |
| ---------- | -------------------------------------------------------- |
| 时间及部门 | 【本地日期、时分；试用部门】                             |
| 页面与操作 | 【入口路径；按钮原文；本人／部门范围】                   |
| 样本与步骤 | 【批准样本编号；最短复现步骤】                           |
| 预期与实际 | 【希望发生什么；页面实际提示；是否已生成记录或下载】     |
| 证据       | 【脱敏截图；页面若提供requestId则一并记录】              |
| 后续动作   | 【是否刷新、重登或使用过原请求恢复；不要为截图重复提交】 |

## 6. 已有能力与验证边界

| 层次             | 当前说明                                                                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 已实现           | 上述正式入口及其按权限开放的业务操作；内部报表中心、即时CSV、独立读取／导出权限、案件办理组及材料相关能力均已有代码                                                |
| 本批有限真实验证 | 已有隔离样本完成部分案件来源、判决至归档、报表读取、原生CSV下载字节核对；撤销部门导出授权后，新会话读取仍可用、导出返回403；办理组／材料与注销也有各自有限技术证据 |
| 不能据此推出     | 所有业务场景一次性全流程通过、全部角色和非空公证场景已验、完整并发覆盖、所有客户／律师分支已验，或已部署UAT／生产                                                  |
| 待人工试用       | 真实运营账号在最终批准权限下的端到端操作、业务文案与数据口径确认、目标访问地址和实际浏览器环境体验                                                                 |

外部报表历史、模板整包迁移和OCR仅是未启动候选，不列为本期试用前置。人工测试账号增权及人工真实验证按用户安排放在功能开发完成之后；UAT部署、迁移、备份及恢复等环境准备仍由交付负责人单独确认。

## 根因

待归档阶段有三条动作路径，各自渲染不同面板：

| 意图                | 面板                           |
| ------------------- | ------------------------------ |
| `settlement-update` | 结算面板（只有付款/退费/回款） |
| `record-closure`    | 结案资料登记表单               |
| `correct-closure`   | 结案资料更正表单               |

列表按案件能力值选意图，同一句「结案更新」落到不同分支，所以第 2、3 行打开的是两张卡。

## 修复

`CaseListWorkflowPanel` 把三种意图合并到同一分支：

1. 顶部固定渲染 `CaseClosurePanel`（结案信息、历史、更正入口）
2. 下方在 `canUpdateClosureSettlement` 时渲染「结算与回款」段
3. 删除原先独立的 `settlement-update` 分支，避免双份
4. `settlement-update` 不再被外层 `fieldset` 排除，与结案段共享禁用状态
